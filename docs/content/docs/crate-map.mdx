# Crate Map

The Bricks workspace is at version 0.6.1. Its crates are named `bricks-*`,
except the facade, `bricks`. Each crate lives under `crates/`, and the two
applications under `apps/`. The workspace layers are described in
[Architecture](/docs/architecture).

## Frontends

| Path | Package | What it is |
|---|---|---|
| `crates/bricks-cli` | `bricks-cli` (binary `bricks`) | The command. Parses arguments, loads the configuration, starts the engine, and presents its events as text or as versioned JSONL: `bricks run`, `bricks sessions`. Installed with `cargo install --path crates/bricks-cli`. |
| `apps/bricks-desktop` | `bricks-desktop` (product "Bricks") | Bricks Desktop, the interactive interface. A Tauri 2 application with a Svelte front end. It renders the engine's events and turns the person's actions into engine commands. It holds no agent logic. |

The command and the desktop application use the engine's command/event
contract, `bricks_agent::control`. The commands and the output format of the `bricks` command are in
`docs/cli.md` in the repository.

## The facade

| Crate | Role |
|---|---|
| `bricks` | Re-exports the workspace under one name: `bricks::prelude::*` for the common types, and modules such as `bricks::tools`, `bricks::provider`, `bricks::memory`, `bricks::hooks`, `bricks::mcp` and `bricks::skills`. |

Feature flags of the facade:

| Feature | Default | Enables |
|---|---|---|
| `vms` | yes | `bricks::vms` (`bricks-vms`) |
| `agentlang` | no | `bricks::agentlang` (`bricks-agentlang`) |
| `agentrl` | no | `bricks::agentrl` (`bricks-agentrl`); implies `agentlang` and `vms` |
| `workflows` | no | `bricks::workflows` (`bricks-workflows`) |

Providers are configuration, not types: the facade exports
`provider_from_config`, `ProviderRegistry`, `ConfiguredProvider` and
`ResolvedModel` from `bricks-provider`.

## The engine

| Crate | Role |
|---|---|
| `bricks-agent` | The `Agent` builder, the agentic loop, the context manager with compaction, the approval gate, the sub-agent tools (`Agent`, `Agents`, `AgentControl`, `AgentProfiles`), and the command/event contract in `control`. |
| `bricks-config` | The assembly the frontends share: the Bricks home folder, the provider registry, the project loader and the engine configuration. |

## Services

| Crate | Role |
|---|---|
| `bricks-types` | Messages, content blocks, errors (`CerseiError`), stream events, and the shared HTTP client (`bricks_types::http`). It depends on no other workspace crate. |
| `bricks-provider` | The `Provider` trait, the provider registry read from `providers.toml`, and the three protocol adapters: `chat_completions`, `responses` and `anthropic_messages`. Retries, prices and reasoning profiles. |
| `bricks-tools` | The `Tool` trait and the built-in tools, grouped in sets: `all()`, `coding()`, `filesystem()`, `shell()`, `web()` and `planning()`. Also the `PermissionPolicy` trait, the change previews, and the shell sessions and background jobs. |
| `bricks-tools-derive` | The `#[derive(Tool)]` procedural macro. |
| `bricks-memory` | The `Memory` trait and its backends: JSONL session storage, an in-memory store, the memory directory, the CLAUDE.md loader. Graph memory (`graph` feature) and structured long-term memory (`structured`) are feature-gated. |
| `bricks-embeddings` | Embedding providers behind one trait, and a USearch vector index. |
| `bricks-compression` | Reduction of tool outputs: command-aware rules and tree-sitter skeletons of long files. |
| `bricks-semantic` | The code understanding engine shared per workspace: lexical search, syntax context, and optional language servers. It backs `CodeScout` and `/search`. |
| `bricks-lsp` | The language server client. |
| `bricks-web` | Web search with provider fallback, bounded fetching with SSRF filtering, Markdown extraction and passage selection. |
| `bricks-mcp` | The MCP client over stdio and Streamable HTTP. |
| `bricks-skills` | Agent Skills (`SKILL.md`): format and validation, the skill store (`<bricks_home>/skills`), the built-in `create-skills`, trust of configured project sources, activation. Re-exported as `bricks::skills`. |
| `bricks-hooks` | The `Hook` trait, hook events and actions, and `ShellHook`. |
| `bricks-vms` | Sandboxes and VM isolation. |
| `bricks-agentlang` | The AgentTemplate language: a lexer, parser and interpreter that run agent templates on top of the tools. |
| `bricks-agentrl` | AgentRL, the self-evolving orchestration layer: the execution graph, the planner, the dynamic tool registry and the verifiers. |
| `bricks-workflows` | A serialisable workflow engine. |

## The `Skill` tool

The `Skill` tool is implemented in `bricks-tools`, but it is not part of the
tool sets above. The engine adds it to an agent that has skills, set with
`AgentBuilder::skills` from `bricks-skills`.

## Other crates

| Crate | Role |
|---|---|
| `bricks-testkit` (not published) | Test helpers for the workspace: a local scripted HTTP server. |
| `bricks-tbench` | The Terminal-Bench coding agent, built on the engine and AgentRL. Its binary is `tbench-agent`. |
| `longmem-bench` (in `bench/long-mem`, not published) | The LongMemEval benchmark for the memory stack, with the binary `longmem-recall`. |

`bricks-cli` and `bricks-desktop` are not library crates, and the publication
script leaves them out. The publication order and the list of published crates
are in `docs/maintenance.md` in the repository.
