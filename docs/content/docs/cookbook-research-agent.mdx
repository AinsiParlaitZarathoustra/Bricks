# Cookbook: Research Agent

This recipe builds an agent that researches a question by searching the web, reading pages, searching local code, and recording what it finds. The web tools are described in `docs/web.md` in the repository. The search provider is set in `bricks.toml` under `[web.search]`.

```text
User query → research agent
  ├── WebSearch / WebFetch   → results and page passages
  ├── Read / Glob / Grep     → local code and documents
  ├── LspTool                → code symbols and references
  └── GraphMemory            → store and recall findings
```

## The agent

```rust
use bricks::prelude::*;
use bricks::tools::{lsp_tool::LspTool, filesystem, web};
use std::path::Path;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let provider = bricks::provider_from_config(None, "my-provider/my-model")?;

    // Read, Write, Edit, Glob, Grep, … ; WebFetch and WebSearch; the LSP tool.
    let mut tools: Vec<Box<dyn Tool>> = Vec::new();
    tools.extend(filesystem());
    tools.extend(web());
    tools.push(Box::new(LspTool::new(Path::new("."))));

    let agent = Agent::builder()
        .provider(provider)
        .tools(tools)
        .system_prompt(RESEARCH_PROMPT)
        .auto_compact(true)
        .session_id("research-session-1")
        .working_dir(".")
        .build()?;

    let output = agent.run(
        "Research the current state of Rust async runtimes. Compare tokio, async-std, smol \
         and glommio on performance evidence, API ergonomics and ecosystem maturity. Cite each \
         source by URL. Write the report to research-output.md.",
    ).await?;

    println!("Research complete in {} turns, {} tool calls", output.turns, output.tool_calls.len());
    Ok(())
}

const RESEARCH_PROMPT: &str = "You are a research agent. Your job is to:
1. Break the question into sub-topics
2. Search the web for each sub-topic with WebSearch
3. Read the promising pages with WebFetch
4. Cross-check the claims against local code with Grep and Glob
5. Use the LSP tool to understand library code when it matters
6. Write a report with a comparison table and a source list

Cite every source by URL. Give the strongest evidence for each claim, and say when the evidence is weak.";
```

`filesystem()` and `web()` are the tool sets of the same names in `bricks::tools`. The `session_id` makes the conversation resumable when a memory is attached; see [Agent Deployment](/docs/cookbook-agent-deployment#with-session-persistence).

## Several questions in parallel

A research question with independent parts can be split in code, with one agent per part, run concurrently. Each agent gets its own history:

```rust
let parts = [
    "Performance evidence for tokio, smol and glommio",
    "Current maintenance status of async-std",
    "Ecosystem size and the crates that depend on each runtime",
];

let runs = parts.iter().map(|question| {
    let agent = Agent::builder()
        .provider(bricks::provider_from_config(None, "my-provider/my-model").unwrap())
        .tools(web())
        .system_prompt(RESEARCH_PROMPT)
        .build()
        .unwrap();
    let question = question.to_string();
    async move { agent.run(&question).await }
});

let answers = futures::future::join_all(runs).await;
```

`join_all` comes from the `futures` crate. Then ask a final agent to combine the answers. This keeps the coordination in your code, where you can see it, instead of in the model's choice of tools.

## Persistent findings with graph memory

Store findings in a graph store and recall them in later sessions. This needs the `graph` feature of `bricks-memory` (see [Graph Memory](/docs/cookbook-graph-memory)):

```rust
use bricks::memory::graph::GraphMemory;
use bricks::memory::memdir::MemoryType;
use std::path::Path;

let graph = GraphMemory::open(Path::new("./research.db"))?;

let id = graph.store_memory(
    "tokio: <throughput figure and source URL, as found>",
    MemoryType::Reference,
    0.9,
)?;
graph.tag_memory(&id, "rust-async")?;
graph.tag_memory(&id, "benchmarks")?;

let id2 = graph.store_memory(
    "async-std: <status statement and source URL, as found>",
    MemoryType::Reference,
    0.85,
)?;
graph.link_memories(&id, &id2, "COMPARES_TO")?;

// In a later session:
for finding in graph.by_topic("rust-async") {
    println!("{finding}");
}
```

Store the text of a finding, with its source, and not only a conclusion, so that a later session can check it.

<Callout type="info">
Put recalled findings into the prompt of the next session yourself. [Graph Memory](/docs/cookbook-graph-memory#using-it-with-an-agent) shows how to combine `MemoryManager::recall` with `build_context()`. The graph store is not a conversation memory.
</Callout>

## The report format

The agent's report is Markdown. A typical layout is a summary, a comparison table, and a source list. The table below is a **template**: the cells are placeholders for what the research finds, not measured results.

```markdown

## Summary
…

| glommio | …                    | …              | …         | …      |

…
```
