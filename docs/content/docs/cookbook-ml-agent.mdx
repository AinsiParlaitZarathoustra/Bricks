# Cookbook: ML Coding Agent

This recipe builds an agent that reads an ML codebase, runs training scripts, and reports the results. It adds two custom tools to the coding tools, uses the code-intelligence primitive to find model definitions, and records experiments in graph memory.

<Callout type="warn">
The agent in this recipe runs `python` commands the model writes, with the permissions you give it. Run it in a project you are willing to let it change, and approve its tool calls, or use a permission policy that asks.
</Callout>

## The agent

```rust
use async_trait::async_trait;
use bricks::prelude::*;
use bricks::tools::{PermissionLevel, Tool, ToolContext, ToolResult};
use std::sync::Arc;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // provider_id/model_id from ~/.bricks/providers.toml
    let selection = std::env::args().nth(1).unwrap_or_else(|| "my-provider/my-model".into());

    let mut tools = bricks::tools::coding();   // Read, Write, Edit, Glob, Grep, Bash, …
    tools.push(Box::new(TrainTool));
    tools.push(Box::new(GpuStatusTool));

    let agent = Arc::new(
        Agent::builder()
            .provider(bricks::provider_from_config(None, &selection)?)
            .tools(tools)
            .system_prompt(ML_SYSTEM_PROMPT)
            .max_tokens(16384)
            .working_dir(".")
            .build()?,
    );

    let mut stream = agent.run_stream(
        "Read model.py and describe the architecture. Then train for 5 epochs and report \
         the loss curve. If val_loss plateaus, suggest architecture changes.",
    );

    while let Some(event) = stream.next().await {
        match event {
            AgentEvent::TextDelta(t) => print!("{t}"),
            AgentEvent::ToolStart { name, .. } => eprintln!("\n  > {name}"),
            AgentEvent::ToolEnd { name, duration, .. } => {
                eprintln!("  < {name} ({:.1}s)", duration.as_secs_f64());
            }
            AgentEvent::Complete(_) => break,
            _ => {}
        }
    }

    Ok(())
}

const ML_SYSTEM_PROMPT: &str = "You are an ML engineering agent. You can:
- Read and understand model architectures (PyTorch, TensorFlow, MLX)
- Run training scripts and capture metrics
- Analyze loss curves and suggest improvements
- Modify hyperparameters and model code

Check the GPU status before training. Report metrics in tables.";
```

`run_stream` returns an `AgentStream`, whose `next()` yields the events until `Complete`. The agent must be in an `Arc`, because the stream keeps a reference to it.

## Custom tools

### Train

Runs a Python script in the working directory, with a timeout:

```rust
struct TrainTool;

#[async_trait]
impl Tool for TrainTool {
    fn name(&self) -> &str { "Train" }
    fn description(&self) -> &str {
        "Run a Python training script in the project. Returns stdout and stderr."
    }
    fn permission_level(&self) -> PermissionLevel { PermissionLevel::Execute }

    fn input_schema(&self) -> serde_json::Value {
        serde_json::json!({
            "type": "object",
            "properties": {
                "script": { "type": "string", "description": "Python script to run, e.g. train.py" },
                "args": { "type": "string", "description": "Command-line arguments", "default": "" },
                "timeout_secs": { "type": "integer", "default": 600 }
            },
            "required": ["script"]
        })
    }

    async fn execute(&self, input: serde_json::Value, ctx: &ToolContext) -> ToolResult {
        let script = input["script"].as_str().unwrap_or("train.py");
        let args = input["args"].as_str().unwrap_or("");
        let timeout = input["timeout_secs"].as_u64().unwrap_or(600);

        // The script and arguments come from the model. Check them before they reach a shell.
        let cmd = format!("python {script} {args}");
        let opts = bricks::tools::tool_primitives::process::ExecOptions {
            cwd: Some(ctx.working_dir.clone()),
            timeout: Some(std::time::Duration::from_secs(timeout)),
            ..Default::default()
        };

        match bricks::tools::tool_primitives::process::exec(&cmd, opts).await {
            Ok(output) => {
                let mut result = output.stdout.clone();
                if !output.stderr.is_empty() {
                    result.push_str("\n--- stderr ---\n");
                    result.push_str(&output.stderr);
                }
                if output.timed_out {
                    ToolResult::error(format!("Training timed out after {timeout}s\n{result}"))
                } else if output.exit_code != 0 {
                    ToolResult::error(format!("Training failed (exit {})\n{result}", output.exit_code))
                } else {
                    ToolResult::success(result)
                }
            }
            Err(e) => ToolResult::error(format!("Failed to start training: {e}")),
        }
    }
}
```

### GPU status

Reports the NVIDIA GPU when `nvidia-smi` works, and otherwise checks PyTorch's MPS backend:

```rust
struct GpuStatusTool;

#[async_trait]
impl Tool for GpuStatusTool {
    fn name(&self) -> &str { "GpuStatus" }
    fn description(&self) -> &str { "Check GPU availability and memory usage." }
    fn permission_level(&self) -> PermissionLevel { PermissionLevel::ReadOnly }

    fn input_schema(&self) -> serde_json::Value {
        serde_json::json!({ "type": "object", "properties": {} })
    }

    async fn execute(&self, _input: serde_json::Value, _ctx: &ToolContext) -> ToolResult {
        use bricks::tools::tool_primitives::process::{exec, ExecOptions};

        if let Ok(out) = exec(
            "nvidia-smi --query-gpu=name,memory.used,memory.total,utilization.gpu --format=csv,noheader",
            ExecOptions::default(),
        ).await {
            if out.exit_code == 0 {
                return ToolResult::success(format!("NVIDIA GPU:\n{}", out.stdout));
            }
        }

        match exec(
            "python -c \"import torch; print(f'MPS available: {torch.backends.mps.is_available()}')\"",
            ExecOptions::default(),
        ).await {
            Ok(out) if out.exit_code == 0 => ToolResult::success(format!("Apple Silicon:\n{}", out.stdout)),
            _ => ToolResult::success("No GPU detected. Training will use CPU."),
        }
    }
}
```

## Finding the model definitions

Before the agent edits model code, the code-intelligence primitive can list the classes and functions of the project. `scan_project` parses up to the given number of files with tree-sitter:

```rust
use bricks::tools::tool_primitives::code_intel;
use std::path::Path;

for intel in code_intel::scan_project(Path::new("./"), 20) {
    let models: Vec<_> = intel.symbols.iter()
        .filter(|s| s.name.contains("Model") || s.name.contains("Net"))
        .collect();
    if !models.is_empty() {
        println!("{}:", intel.path.display());
        for sym in models {
            println!("  {} {} (line {})", sym.kind.label(), sym.name, sym.line);
        }
    }
}
```

## Experiment tracking with graph memory

Record each run in a graph store, so that a later session can find the results. This needs the `graph` feature of `bricks-memory` (see [Graph Memory](/docs/cookbook-graph-memory)):

```rust
use bricks::memory::graph::GraphMemory;
use bricks::memory::memdir::MemoryType;
use std::path::Path;

let graph = GraphMemory::open(Path::new("./memory.db"))?;

let id = graph.store_memory(
    "experiment: lr=1e-4, epochs=10, val_loss=0.23, val_acc=0.91",
    MemoryType::Project,
    0.95,
)?;
graph.tag_memory(&id, "experiment-results")?;

// In a later session:
let results: Vec<String> = graph.by_topic("experiment-results");
```

`by_topic` returns the matching memories as text. It does not sort them.

## An illustrative flow

This shows the shape of a session. It is not a recorded run, and the numbers are placeholders:

```text
User: "Train the model on the new dataset and compare with the last run"

Agent:
1. [GpuStatus]  → MPS available: True
2. [Read]       model.py → the architecture is a small convolutional network
3. [Grep]       "val_loss" in the training logs → the last run reached val_loss=<last value>
4. [Train]      python train.py --data new_dataset --epochs 10
5. [Memory]     store the new result, tagged as an experiment
6. The reply compares the two runs in a table
```
