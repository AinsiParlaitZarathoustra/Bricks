# Built-in Tools Reference

38 tools in the categories below. Each tool is available via the composition functions in `bricks::tools`. The sub-agent tools (`Agent`, `Agents`, `AgentControl`, `AgentProfiles`) are not in those sets: see [Sub-agent tools](#sub-agent-tools).

```text
bricks::tools::all()           // all 38
bricks::tools::coding()        // filesystem + shell + web (17)
bricks::tools::filesystem()    // 9 tools
bricks::tools::shell()         // 6 tools
bricks::tools::web()           // 2 tools
bricks::tools::planning()      // 3 tools
bricks::tools::scheduling()    // 5 tools
bricks::tools::orchestration() // 9 tools
```

### Edit

Replace text in a file, with one replacement (`old_string`, `new_string`) or several (`edits`). Several replacements are applied in order, each against the result of the previous one, and the file is written only if all of them apply. Fails if an `old_string` is not unique (unless `replace_all` is true). No `Read` is needed first: the change is decided on what it would do to the file. The file is written under a per-file lock, and not at all if it changed after its change was approved (the call is then decided again). Replaces the former `MultiEdit`, which no longer exists.

**Permission:** Write

<TypeTable
  type={{
    file_path: {
      type: 'string',
      description: 'Absolute path to the file.',
      required: true,
    },
    old_string: {
      type: 'string',
      description: 'One replacement: the text to find. Use with new_string, not with edits.',
    },
    new_string: {
      type: 'string',
      description: 'One replacement: the replacement text. Omit it, or give an empty string, to delete old_string.',
    },
    replace_all: {
      type: 'boolean',
      description: 'Replace all occurrences instead of requiring uniqueness.',
      default: 'false',
    },
    edits: {
      type: 'array',
      description: 'Several replacements, in order: entries of { old_string, new_string?, replace_all? }. Use instead of old_string, new_string and replace_all, not with them. Non-empty.',
    },
  }}
/>

## Shell

### Bash

Execute a shell command. Each call is its own process, started from the session's state. When it ends normally, its working directory, exported variables, functions and aliases persist for the next calls; commands of a session run side by side.

**Permission:** Execute

<TypeTable
  type={{
    command: {
      type: 'string',
      description: 'The bash command to execute.',
      required: true,
    },
    timeout: {
      type: 'integer',
      description: 'Timeout in milliseconds.',
      default: '120000 (max 600000)',
    },
    yield_time_ms: {
      type: 'integer',
      description: 'Foreground only: milliseconds before a command still running is handed over as a task (status Running, with task_id and job_id). Not a deadline.',
      default: '[bash] yield_time_ms (10000)',
    },
    background: {
      type: 'boolean',
      description: 'Start a supervised background task at once.',
      default: 'false',
    },
  }}
/>

<Callout>
Bash calls are approved by the permission policy at the `Execute` level, whatever the command. No analysis of the command runs before it and none lowers or raises that level. The AST analysis of `bricks_tools::tool_primitives::bash_safety` is an SDK primitive a caller can use on its own; see [Code intelligence](/docs/code-intelligence#bash-command-safety-analysis).
</Callout>

## Orchestration

### SendMessage

Send a message to one of your running sub-agents. It is the same delivery as `AgentControl message` (see [Sub-agent tools](#sub-agent-tools)): the sub-agent reads it at its next model request, never between a tool call and its result. Refusals are explicit (unknown or out of scope, not running, empty, over 16 KiB, 32 messages already waiting); nothing is reported as sent when it was not. Without an agent runtime in the session, nothing is sent.

**Permission:** Execute

<TypeTable
  type={{

      type: 'string',
      description: 'The sub-agent ID (`agent_…`).',
      required: true,
    },
    content: {
      type: 'string',
      description: 'Message content.',
      required: true,

### Sub-agent tools

`Agent` (one sub-agent), `Agents` (several), `AgentControl` (ids, results,
messages, resumes, cancellation and ChangeSets) and `AgentProfiles` (list and
search the profiles) are native tools. The CLI and the controller register
them when `[agents] enabled` is true (the default). They are not in
`bricks::tools::all()`, and the library type `AgentTool` stays for embedders.

Sub-agents always run in parallel. `Agent` and `Agents` return their ids at
once; `AgentControl wait` and `result` give the results. There is no
`background` parameter.

**Permission:** `Agent` and `Agents`: Execute. Allowing one allows that
delegation only: each child's own tool calls go through the policy one by one.
`AgentControl`: ReadOnly for `list`, `status`, `result`, `wait` and
`inspect_changes`, Execute for `message`, `resume` and `cancel`, Write for
`apply_changes` and `discard_changes`. `AgentProfiles`: ReadOnly.

The `AgentControl` actions, by their parameters:

| action | parameters | effect |
|---|---|---|
| `list`, `status`, `result` | `agent_id` (`status`, `result`) | instances visible to the caller; state; the kept result |
| `wait` | `agent_id`, `timeout_ms` (default 60000, at most 600000) | waits for the end; a timeout cancels nothing |
| `message` | `agent_id`, `message` | queues a message for a running sub-agent (see `SendMessage`) |
| `resume` | `agent_id`, `prompt` | starts a new execution of an ended sub-agent, with its launch's profile, model, tools, skills and workspace |
| `cancel` | `agent_id` | cancels it and its descendants |
| `inspect_changes`, `apply_changes`, `discard_changes` | `changeset_id` or `agent_id` | a ChangeSet of an isolated sub-agent |

Their parameters, the limits (`max_depth`, `max_concurrent` = 16, `max_queued`
= 64, `admission_timeout_ms` = 60000, `summary_chars` = 10000) and the
isolation rules are in `docs/agents.md` in the repository.

### Skill

Activates an [Agent Skill](https://agentskills.io/specification) — reads its full instructions — or lists the skills the agent may activate, or locates one of a skill's files. It runs nothing and grants no permission. Present only on agents built with a skills service (`AgentBuilder::skills`; the `bricks` CLI does it).

**Permission:** ReadOnly

<TypeTable
  type={{
    action: {
      type: 'string',
      description: '"activate" (default when `skill` is given), "list", or "resource". `skill: "list"` without an action lists.',
    },
    skill: {
      type: 'string',
      description: 'The skill name, exactly as listed.',
    },
    args: {
      type: 'string',
      description: 'The request to apply the skill to; returned separately, never substituted into the instructions.',
    },
    query: {
      type: 'string',
      description: 'For "list": words to filter names and descriptions (20 per page, `page`).',
    },
    path: {
      type: 'string',
      description: 'For "resource": a path relative to the skill\'s directory.',
    },
  }}
/>

See `docs/skills.md` in the repository for sources, trust, activation and limits.
