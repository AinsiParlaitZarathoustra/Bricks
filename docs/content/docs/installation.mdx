## From crates.io

The snippets below pin the workspace version, 0.6 (every crate inherits `version.workspace`, 0.6.0). If Cargo cannot resolve these versions from the registry, use the git source described under [Tracking `main`](#tracking-main).

```toml
[dependencies]
cersei = "0.6"
tokio = { version = "1", features = ["full"] }
anyhow = "1"
```

Or via the CLI:

```bash
cargo add cersei
cargo add tokio --features full
cargo add anyhow
```

## Optional: Graph Memory

Enable the Grafeo graph backend for relationship-aware recall:

```toml
cersei-memory = { version = "0.6", features = ["graph"] }
```

## Optional: Individual Crates

Use specific crates if you only need parts of the SDK:

```toml
cersei-types       = "0.6"   # Core types only
cersei-provider    = "0.6"   # LLM providers
cersei-tools       = "0.6"   # Tool system
cersei-tools-derive = "0.6"  # #[derive(Tool)] proc macro
cersei-agent       = "0.6"   # Agent runtime
cersei-memory      = "0.6"   # Memory backends
cersei-hooks       = "0.6"   # Hooks / middleware
cersei-mcp         = "0.6"   # MCP client
cersei-lsp         = "0.6"   # LSP client
cersei-embeddings  = "0.6"   # Embeddings + vector index
cersei-compression = "0.6"   # Token-killer compression
bricks-skills      = "0.6"   # Agent Skills (formerly cersei-skills)
cersei-vms         = "0.6"   # Sandbox / VM isolation
```

`bricks-skills` can also be taken from this repository, by git or by path.

## Bricks CLI

The `bricks` command is built from a checkout of the Bricks repository:

```bash
cargo install --path crates/bricks-cli
```

It reads its models from `~/.bricks/providers.toml`; see `docs/cli.md` and
`docs/providers.md` in the repository. The Cersei-era `abstract-cli` crate is no
longer in this workspace, and `bricks` does not install it.

## Tracking `main`

If you need an unreleased fix, point at the GitHub repo instead:

```toml
cersei = { git = "https://github.com/pacifio/cersei" }
```

## Environment Variables

No variable name is read implicitly. Each provider entry in `~/.bricks/providers.toml` names the environment variable that holds its key, with `api_key_env` (see `docs/providers.md` and `docs/providers.example.toml`).

## System Requirements

- A recent stable Rust: edition 2024, 1.88 or later (let chains); tested with 1.98
- No external search tool is needed: the `Grep` tool is built in (it uses the `grep` and `ignore` crates)
- macOS, Linux, or Windows
