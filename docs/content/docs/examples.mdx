# Examples

The examples of the facade are in `crates/bricks/examples`. Each one is a Rust
program. Run one from the root of the workspace:

```bash
cargo run -p bricks --example <name>
```

Add `--release` for timings. The examples of the facade compile with the current
workspace (`cargo check -p bricks --examples`).

**Some examples allow every tool.** `simple_agent` and the examples that use
`AllowAll` can write files and run commands in the folder they are started
from. Run them in a scratch folder, or change the policy to `AllowReadOnly`.

## Examples that call a model

These take the model as a `provider_id/model_id` argument, read from the
providers file. The [quick start](/docs/quick-start) shows how to configure one.

```bash
cargo run -p bricks --example simple_agent -- acme/fast
```

| Example | What it shows |
|---|---|
| `simple_agent` | An agent with the coding tools, one prompt, and the answer printed. |
| `streaming_events` | `run_stream()`, with text deltas, tool starts and ends, and cost updates as they arrive. |
| `custom_tools` | Custom tools, with `#[derive(Tool)]` and with the raw `Tool` trait. |
| `hooks_middleware` | Hooks that intercept tool calls, such as a cost guard that stops the run when spending exceeds a budget. |
| `multi_listener` | The broadcast channel, with several consumers of the same run. |
| `resumable_session` | A conversation persisted with `JsonlMemory` and resumed by a second run. |
| `multimodal` | Images, audio or PDFs attached to a message, when the model accepts them. |
| `coding_agent` | An end-to-end run: an agent builds a small Python command-line program. |
| `usage_report` | Token and cost tracking across several turns. It uses a simulated provider, so it needs no model. |

## Examples that need no model

| Example | What it shows |
|---|---|
| `custom_provider` | How to write a provider, with a local echo provider as the example. |
| `benchmark_io` | The in-process cost of the file and shell tools, measured over repeated calls. |
| `stress_core_infrastructure` | The system prompt builder, compaction and the Bash command analysis. |
| `stress_tools` | Every tool that can run without external services: schemas, execution and the registry. |
| `stress_orchestration` | Sub-agents, the coordinator, the task tools and messages between agents. Uses a local echo provider. |
| `stress_skills` | Agent Skills: sources, trust, and the `Skill` tool, on temporary folders only. |
| `stress_memory` | Memdir, the CLAUDE.md loader, session storage and graph memory. |

The `stress_*` examples check behaviour. They are not performance measurements.

## Examples of other crates

| Crate | Example | Command | What it shows |
|---|---|---|---|
| `bricks-compression` | `show` | `cargo run -p bricks-compression --example show -- <file> <tool> <command-or-path> [level]` | How one output or file is reduced. |
| `bricks-compression` | `measure` | `cargo run -p bricks-compression --example measure` | The reductions on the fixture corpus and on real files. |
| `bricks-memory` | `memory_bench` | `cargo run -p bricks-memory --features graph --example memory_bench` | The memory operations on local files and an in-process graph. |
| `bricks-memory` | `measure_memory` | `cargo run -p bricks-memory --features structured --example measure_memory` | The latency of structured memory on synthetic corpora. |
| `bricks-tools` | `semantic_bench` | `cargo run -p bricks-tools --example semantic_bench` | One `CodeScout` query against the `Grep` and `Read` path, on the corpus in `bench/semantic`. |
| `bricks-web` | `measure_web` | `cargo run -p bricks-web --example measure_web` | The web pipeline on a local corpus: HTML, then Markdown, then passages. |
