# bricks-embeddings

`bricks-embeddings` turns text into vectors and searches them. It has an `EmbeddingProvider` trait, with hosted providers (OpenAI, Gemini) and a local, offline one (`HashingEmbeddings`), and a `VectorIndex` built on `usearch` (HNSW). You can use it alone for search and retrieval, and Bricks uses it in two places: long-term memory and the `CodeSearch` tool.

<Callout type="info">
The crate depends on `bricks-types` for its shared HTTP client, and on no other Bricks crate. It can be used without the agent.
</Callout>

## When to use it

- **Semantic search** over documents, notes or code.
- **Retrieval for RAG**: fetch the snippets to put in a prompt.
- **Deduplication or clustering** by nearest-neighbour distance.
- **Reranking** on top of another retriever.

For keyword search over code inside an agent, `CodeSearch` already includes BM25. Add embeddings when you need matches by meaning.

## What ships in the box

| Piece | Role |
|---|---|
| `EmbeddingProvider` | The trait every backend implements: `name`, `dimensions`, `model_id`, `embed`, `embed_batch`. |
| `OpenAiEmbeddings` | OpenAI embeddings. Default model `text-embedding-3-small`, 1536 dimensions. The base URL can be changed, for an OpenAI-compatible endpoint. |
| `GeminiEmbeddings` | Google Gemini embeddings. Default model `gemini-embedding-001`, 3072 dimensions by default; a smaller size can be requested with `with_dimensions`. |
| `HashingEmbeddings` | A local, deterministic embedder using feature hashing of words and word pairs. No network and no key. It is lexical: paraphrases with no shared word are not close. |
| `VectorIndex` | A `usearch` HNSW index with `Metric::Cosine`, `L2` or `InnerProduct`. |
| `EmbeddingStore<P>` | A provider and an index together, for "add text, search by text". |
| `auto_from_model` | Chooses OpenAI or Gemini from an LLM model string. |
| `SearchHit` | `{ key, distance, similarity }`. |

## Add it to a project

```toml
[dependencies]
bricks-embeddings = "0.6"
```

## Quick start

<Tabs items={['OpenAI', 'Gemini', 'Auto-detect']}>
<Tab value="OpenAI">
```rust
use bricks_embeddings::{OpenAiEmbeddings, EmbeddingStore, Metric};

let provider = OpenAiEmbeddings::from_env()?;          // reads OPENAI_API_KEY
let store = EmbeddingStore::new(provider, Metric::Cosine)?;

store.add_batch(&[
    (1, "Rust is a systems programming language".into()),
    (2, "Pasta is best served al dente".into()),
]).await?;

let hits = store.search("compiled languages", 2).await?;
assert_eq!(hits[0].key, 1);
```
</Tab>
<Tab value="Gemini">
```rust
use bricks_embeddings::{GeminiEmbeddings, EmbeddingStore, Metric};

// Reads GOOGLE_API_KEY, or GEMINI_API_KEY when that is unset.
let provider = GeminiEmbeddings::from_env()?;
let store = EmbeddingStore::new(provider, Metric::Cosine)?;

store.add_batch(&[
    (1, "Rust is a systems programming language".into()),
    (2, "Pasta is best served al dente".into()),
]).await?;

let hits = store.search("compiled languages", 2).await?;
```
</Tab>
<Tab value="Auto-detect">
```rust
use bricks_embeddings::auto_from_model;

// Chooses the provider family from a model string.
let provider = auto_from_model("openai/gpt-4o")?;
println!("{} ({}-d)", provider.name(), provider.dimensions());
```
</Tab>
</Tabs>

## Where Bricks uses it

- **Long-term memory.** In `bricks.toml`, `[memory] embeddings` selects the provider: `hashing[:dims]` (local, the value in the example configuration), `openai[:model]` or `gemini[:model]`. Memory is attached only when `[memory] enabled = true`.
- **CodeSearch.** `CodeSearchTool::with_embeddings(provider)` (in `bricks-tools`) adds a vector score to the BM25 score: 60 % BM25 and 40 % vector. A provider is needed for this; the repository has no command-line flag that sets one.
