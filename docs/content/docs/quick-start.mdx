This page assumes the [installation](/docs/installation) is done: the `bricks` command is built, or the `bricks` crate is a dependency of your project.

## 1. Declare a model

Models come from a providers file, `~/.bricks/providers.toml`. Nothing is built in and nothing is guessed from a model name: a model is always named `provider_id/model_id`. This file declares one OpenAI-compatible server. Its key is read from the environment variable named by `api_key_env`, so the key itself never goes in the file:

```toml
schema_version = 1

[[providers]]
id = "acme"
name = "Acme gateway"
endpoint = "https://api.example.com/v1"
protocol = "chat_completions"
auth = "bearer"
api_key_env = "ACME_API_KEY"

[[providers.models]]
id = "fast"
name = "Fast model"
api_model = "vendor-fast-model"
streaming = true
tool_calls = true

[providers.models.limits]
max_input_tokens = 96000
max_output_tokens = 8000
```

```bash
export ACME_API_KEY="…"   # your key, in the shell that runs bricks
```

A local server needs no key: use `auth = "none"`. The file accepts three wire protocols (`chat_completions`, `responses`, `anthropic_messages`), prices and reasoning profiles. The annotated example is `docs/providers.example.toml` in the repository.

## 2. Run the `bricks` command

Select the model for the project in `bricks.toml`, at the root of the project:

```toml
[agent]
model = "acme/fast"
```

Then, in that folder:

```bash
bricks run "Explain the failing test in src/parser.rs"          # one prompt, answer on stdout
bricks run --json --non-interactive "Analyse the build errors"  # JSONL events, for scripts and CI
bricks sessions                                                 # the sessions of this project
bricks run --session <id> "Continue where we stopped"           # continue one, headless
```

A file change or a shell command waits for your approval in the terminal, with the diff for file changes. Under `--non-interactive` nothing waits: a step that needs approval stops the run with exit code 3. See the `bricks` reference, `docs/cli.md` in the repository, for the output format and the exit codes.

## 3. Run an agent from Rust

Add the crate as described in [Installation](/docs/installation). This program asks a question about the project. It gives the agent the coding tool set, and it allows only the read-only tools, so the agent can read and search but cannot write or run commands:

```rust
use bricks::prelude::*;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let output = Agent::builder()
        .provider(provider_from_config(None, "acme/fast")?) // ~/.bricks/providers.toml
        .tools(bricks::tools::coding())
        .permission_policy(AllowReadOnly)
        .run_with("What files are in the current directory?")
        .await?;

    println!("{}", output.text());
    Ok(())
}
```

`provider_from_config(None, …)` reads `~/.bricks/providers.toml`; pass a path instead of `None` to read another file. `run_with` runs the loop until the model gives a final answer, and returns the answer with its usage and tool calls.

## 4. Stream the events

`run_stream` returns the events of a run as they happen. The agent is shared in an `Arc` for that:

```rust
use std::sync::Arc;

use bricks::prelude::*;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let agent = Arc::new(
        Agent::builder()
            .provider(provider_from_config(None, "acme/fast")?)
            .tools(bricks::tools::coding())
            .permission_policy(AllowReadOnly)
            .build()?,
    );

    let mut stream = agent.run_stream("Summarise the README");
    while let Some(event) = stream.next().await {
        match event {
            AgentEvent::TextDelta(text) => print!("{text}"),
            AgentEvent::ToolStart { name, .. } => eprintln!("\n[{name}]"),
            AgentEvent::ToolEnd { name, duration, .. } => {
                eprintln!("[{name} done in {} ms]", duration.as_millis());
            }
            _ => {}
        }
    }
    println!();
    Ok(())
}
```

The stream ends when the run ends. When a policy asks for a decision, the stream carries `AgentEvent::PermissionRequired(request)`; answer it with `stream.respond_permission(request.id, PermissionDecision::Allow)`. `stream.cancel()` stops the run. The policy used above decides every request by itself, so the example never asks.
