# bricks-agentrl — API Reference

Everything below is re-exported under `bricks::agentrl` when the `agentrl` feature of the `bricks` facade is enabled. The crate itself is `bricks-agentrl`. `CerseiRunner` and `CerseiError` keep their names in the code.

## Orchestrator

The loop: lookup, general run, failure trace, proposals, promotion, registration. It is generic over an [`AgentRlRunner`](#agentrlrunner), which holds the mechanism, so the loop can be tested with a mock runner.

```rust
let orchestrator = Orchestrator::new(runner, registry) // Arc<dyn AgentRlRunner>, Arc<ToolRegistry>
    .with_memory(memory)            // Arc<dyn Memory>: record solved problems for recall
    .with_config(config)            // OrchestratorConfig
    .with_id_fn(Arc::new(|| …));    // tool ids; the default is "tool-<uuid>"

let outcome: SolveOutcome = orchestrator.solve("the task").await?;
```

| Method | Signature | Purpose |
|---|---|---|
| `new` | `(Arc<dyn AgentRlRunner>, Arc<ToolRegistry>) -> Self` | Builds the orchestrator. |
| `with_memory` | `(self, Arc<dyn Memory>) -> Self` | Writes a recall hint to memory when a new tool is registered. |
| `with_config` | `(self, OrchestratorConfig) -> Self` | Sets rounds, proposal count, search width, samples and session id. |
| `with_id_fn` | `(self, Arc<dyn Fn() -> String + Send + Sync>) -> Self` | Replaces tool id generation. |
| `registry` | `(&self) -> &Arc<ToolRegistry>` | Borrows the registry. |
| `solve` | `(&self, task: &str) -> Result<SolveOutcome>` | Runs the loop once for a task. |

### `OrchestratorConfig`

```rust
pub struct OrchestratorConfig {
    pub max_rl_rounds: u32,        // plan-and-propose rounds after a failed general run (default 1)
    pub num_proposals: usize,      // proposals per round (default 2)
    pub registry_search_k: usize,  // registry entries pre-loaded for the general run (default 5)
    pub session_id: String,        // memory session (default "agentrl")
    pub num_samples: u32,          // general attempts before planning; the first pass wins (default 1)
}
```

Build it with the struct literal and `..Default::default()`, which fills every field you leave out.

### `SolveOutcome` and `Solved`

```rust
pub struct SolveOutcome {
    pub solved: bool,
    pub how: Option<Solved>,
    pub last_graph: ExecutionGraph,
    pub answer: String,
}

pub enum Solved {
    Directly,              // the general agent passed the verifier; no registered tool used
    ByCachedTool(String),  // the general agent passed and used a registered tool
    ByNewTool(String),     // a proposal passed and was registered under this tool id
}
```

## AgentRlRunner

The mechanism behind the loop. Implement it to control how agents run and where proposals execute; `CerseiRunner` is the built-in implementation.

```rust
#[async_trait]
pub trait AgentRlRunner: Send + Sync {
    async fn run_general(&self, task: &str, available: &[RegistryEntry]) -> GeneralResult;
    async fn plan(&self, trace: &FailureTrace, n: usize) -> Vec<Proposal>;
    async fn run_proposal(&self, proposal: &Proposal) -> ProposalOutcome;
    async fn promote(&self, winner: &ProposalOutcome) {}   // default: no-op
}
```

| Type | Fields |
|---|---|
| `GeneralResult` | `success: bool`, `graph: ExecutionGraph`, `answer: String`, `used_tool: Option<String>` |
| `Proposal` | `id: String`, `goal: String`, `context: String` |
| `ProposalOutcome` | `proposal_id: String`, `passed: bool`, `solution: Option<SolutionSpec>`, `summary: String`, `artifact_dir: Option<PathBuf>` |

A proposal is registered only when it passes **and** carries a `solution`. `artifact_dir` is what `promote` should copy back.

<Callout type="info">
The trait separates the loop from the runtime. The crate's tests drive the orchestrator with a mock runner, which checks the register-then-reuse cycle without any network. See `crates/bricks-agentrl/tests/rl_loop.rs`.
</Callout>

## CerseiRunner

The built-in `AgentRlRunner`. It drives real `Agent`s with a real `Provider`; see [the overview](/docs/agentrl-overview#what-the-production-runner-does) for what each step does.

```rust
let runner = CerseiRunner::new(
        provider_factory,  // ProviderFactory = Arc<dyn Fn() -> Box<dyn Provider> + Send + Sync>
        "./work",          // the working directory the general agent edits
        registry,          // Arc<ToolRegistry>
        verifier,          // Arc<dyn Verifier>
    )
    .with_model("my_provider/my-model")
    .with_general_tools(factory);
```

| Method | Purpose |
|---|---|
| `with_model(s)` | The model given to every agent the runner builds. Set it explicitly. |
| `with_general_tools(ToolsFactory)` | Replaces the general agent's base tools. Registry tools are added on top. Restricting the tools is how the recovery loop is exercised in tests. |
| `with_system_prompt(s)` | Replaces the general agent's system prompt. |
| `with_compression(level)` | Sets the compression level of the agents. |
| `with_proposal_verifier(v)` | Uses a different verifier for proposals. |
| `with_bricks_config(cfg)` | Applies a `bricks.toml` configuration to every agent. |

The general agent's tools are `bricks::tools::coding()`, plus `registry_search` (`RegistrySearchTool`), plus one `DynamicTool` per pre-loaded entry. Proposal agents get `coding()` only.

## ExecutionGraph

A graph of the run, filled passively by `GraphReporter`, which implements `Reporter` for the agent's events.

```rust
let gr = GraphReporter::new();
let agent = Agent::builder()./* … */.reporter(gr.clone()).build()?;
agent.run(task).await?;
let graph: ExecutionGraph = gr.graph();              // a snapshot
let trace: FailureTrace = graph.failure_trace(task); // what the planner reads
```

| Type | Fields and values |
|---|---|
| `ExecutionGraph` | `nodes: Vec<RunNode>`, `edges: Vec<Edge>`, `root: NodeId`. Methods include `node`, `has_failure`, `failure_trace`. |
| `RunNode` | `id`, `kind: NodeKind`, `label`, `status: NodeStatus`, `turn`, `detail: NodeDetail` |
| `NodeKind` | `AgentRun`, `Turn`, `ToolCall` |
| `NodeStatus` | `Running`, `Ok`, `Failed` |
| `Edge` | `from`, `to`, `rel: EdgeRel`, where `EdgeRel` is `Contains`, `FailedAfter` or `Spawned` |
| `FailureTrace` | `problem_statement`, `failing_nodes: Vec<FailurePoint>`, `final_error: Option<String>`, `hypotheses: Vec<String>` |
| `FailurePoint` | `tool`, `input_excerpt`, `error_excerpt`, `turn` |

Every excerpt passes through the scrubber (see [Safety](/docs/agentrl-overview#safety)). `FailureTrace::directionality()` renders the trace as text for a planner prompt.

## ToolRegistry

A persisted list of agent-built tools, with keyword search.

```rust
let registry = ToolRegistry::open("~/.cersei/agentrl")?; // returns Arc<ToolRegistry>; a tilde is not expanded
// or: let registry = ToolRegistry::in_memory();          // for tests

registry.register(entry)?;                      // scrubs, then appends to entries.jsonl
let hits = registry.search("build a parser", 5);
let one = registry.get(&tool_id);
let all = registry.all();
registry.record_success(&tool_id);
let n = registry.len();
```

`open` reads the existing `entries.jsonl` in the directory and creates the directory if needed. `in_memory` keeps nothing on disk.

`search(query, k)` counts how many query terms appear in an entry's name, description or problem domain. Entries with at least one match are ranked by that count, with `success_count` breaking ties.

| Type | Fields |
|---|---|
| `RegistryEntry` | `tool_id`, `name`, `description`, `problem_domain`, `failure_trace: FailureTrace`, `solution: SolutionSpec`, `created_at`, `success_count` |
| `SolutionSpec` | `system_prompt`, `goal_template`, `allowed_tools: Vec<String>`, `snapshot_id: Option<String>` |

The search is keyword-based. No embedding index is used. The `bricks-embeddings` crate is a separate component that could back a future search.

## DynamicTool and RegistrySearchTool

A registered solution becomes a tool the agent can call:

```rust
let tool = DynamicTool::new(entry, replayer); // Tool named after the entry
```

`RegistrySearchTool::new(registry)` is the tool named `registry_search`. It lets an agent look up earlier solutions and returns the matching `tool_id`, `name`, `description` and `success_count`.

`DynamicTool` delegates to a `SolutionReplayer`:

```rust
#[async_trait]
pub trait SolutionReplayer: Send + Sync {
    async fn replay(&self, entry: &RegistryEntry, goal: &str, ctx: &ToolContext) -> ToolResult;
}
```

`CerseiRunner` provides a replayer that starts a fresh coding sub-agent seeded from the solution's `SolutionSpec`.

## Verifier

Decides whether the work is done. The general agent and every proposal are judged by the same verifier.

```rust
#[async_trait]
pub trait Verifier: Send + Sync {
    async fn verify(&self, workdir: &Path) -> VerifyResult;
}

pub struct VerifyResult { pub passed: bool, pub detail: String }
```

Built-in verifiers:

| Verifier | Passes when |
|---|---|
| `CommandVerifier::new(command)` | The command, run with `/bin/sh -c` in the working directory, exits with status 0. Timeout 120 s (field `timeout`). |
| `TestScriptVerifier::new(candidates)` / `default_candidates()` | A test script from the candidate list passes. |
| `ChainVerifier::new(verifiers)` | Every verifier in the list passes. |
| `AcceptVerifier` | Always passes, so every run counts as solved. Use it only when no real check exists. |

<Callout type="warn">
Make the verifier **independent** of what the agent writes. If the agent can write the test, it can make the test pass. Check real behaviour, for example `python3 gcd.py 48 36 | grep -qx 12` or `cargo test` on a suite the agent cannot edit.
</Callout>

## Memory bridge

```rust
bricks_agentrl::memory_bridge::record_solution(
    &memory, session_id, problem, tool_name, tool_id,
).await?;
```

Stores a short, scrubbed hint: the problem, and that a reusable tool with that name and id is registered and can be found with `registry_search`. The orchestrator calls it when `with_memory` is set and a new tool is registered, so the agent's normal memory search can surface it later.

## Secret scrubbing

`bricks_agentrl::scrub::redact(text)` removes API-key shapes (OpenAI-style `sk-…`, `sk-ant-…`, Google `AIza…`, `Bearer …` values) and the values of environment variables whose names look secret. `redact_excerpt(text, max)` also shortens the result. The same scrubbing runs on every string that reaches a trace, a registry entry or a memory hint.
