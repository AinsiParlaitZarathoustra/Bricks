# Comparisons

This page describes Bricks as it is. It does not compare Bricks with other
products. The measurements recorded so far, in `docs/benchmarks-bricks-2026-10-08.md`
in the repository, cover local tools and engine overhead on one machine. They
do not measure coding quality with a live model, and they are not a comparison
with other products.

## What Bricks provides

- **Rust crates to embed.** An agent loop, providers, tools, approvals, context
  management, sessions, memory, skills and MCP, as crates you can depend on
  (see [Crate map](/docs/crate-map)).
- **Providers from a file.** A model is `provider_id/model_id` in
  `providers.toml`. There is no built-in catalogue, and no model is chosen by
  name. Three wire protocols are supported.
- **Tools you select.** The library lets an agent use any subset of the
  built-in tools, or your own tools. The frontends give a session a fixed set,
  described in the `docs/cli.md` of the repository.
- **One approval policy.** The `[permissions]` section of `bricks.toml` applies
  to every frontend. File changes are shown as a diff before they are written.
- **A command for scripts and CI.** `bricks run --json` writes versioned JSONL
  events, and each outcome has an exit code.
- **A desktop application** on the same engine contract, for interactive work.
- **Local sessions** under `~/.bricks/sessions`, resumable in their own folder
  and with their own model.

## When Bricks fits

- You want an agent loop inside your own Rust application, with your own tools,
  providers and event consumers.
- You want one command for prompts in scripts and CI, with documented output.
- You want the agent's model, limits and approvals to be files you review and
  keep in the project.

## What Bricks does not provide yet

- **Validated platforms.** The tests have been run on macOS (arm64) only. Linux
  and Windows have not been validated.
- **MCP servers in the frontends.** The `bricks.toml` file does not configure
  MCP servers yet, and `/mcp` says so. The library can add them with
  `mcp_server`.
- **A full tool set in the frontends.** A `bricks` session gets the coding
  tools, the skill tool and the sub-agent tools. Planning, scheduling and the
  task tools are available to a library user only.
- **A model catalogue.** You declare each model and its limits yourself, and
  the file is the only source of them.

For changes since the Cersei names and behaviour, see the
[migration guide](/docs/migration).
