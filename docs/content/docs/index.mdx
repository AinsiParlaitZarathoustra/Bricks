# Bricks ADK

Bricks ADK (Agentic Development Kit) is a set of Rust crates for building
coding agents. It provides the agent loop, providers configured in a file, a
set of purpose-built tools, an approval policy, context management with
compaction, sessions, long-term memory, Agent Skills and MCP.

Two frontends use the same engine:

- **`bricks`**, the command-line tool, for one prompt, for scripts and for CI.
- **Bricks Desktop**, the interactive application, with projects, conversations
  and approvals.

<Callout type="info">
Bricks is a fork of Cersei, created by Adib Mohsin (Pacifio). Its crates are
named `bricks-*`. The [migration guide](/docs/migration) lists what changed
from the Cersei names and behaviour.
</Callout>

## A first agent

```rust
use bricks::prelude::*;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let output = Agent::builder()
        .provider(provider_from_config(None, "acme/fast")?) // ~/.bricks/providers.toml
        .tools(bricks::tools::coding())
        .permission_policy(AllowReadOnly)
        .run_with("What files are in the current directory?")
        .await?;

    println!("{}", output.text());
    Ok(())
}
```

The model `acme/fast` is declared in `~/.bricks/providers.toml`. The
[quick start](/docs/quick-start) shows that file, and the `bricks` command.

## What is inside

- **The engine.** An agent builder, a loop that streams model answers and runs
  tool calls, a command and event contract shared by the frontends, and
  compaction when the context fills.
- **Providers.** Three wire protocols (`chat_completions`, `responses`,
  `anthropic_messages`), configured in a file with limits, prices and reasoning
  profiles.
- **Tools.** File reading and editing, search, shell commands with background
  jobs, web search and fetching, code understanding, and planning and
  scheduling tools. The library chooses the set; a session of the frontends
  gets the coding set.
- **Approvals.** One policy in `bricks.toml` for every frontend. File changes
  are shown as a diff first.
- **Memory and skills.** Session storage and resumption, structured long-term
  memory (opt-in), and Agent Skills in the `SKILL.md` format.
- **MCP.** A client over stdio and Streamable HTTP.
- **Sub-agents.** Native tools to start sub-agents with their own context, and
  to run several at once.
