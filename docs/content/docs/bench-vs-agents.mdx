# Agent Framework Benchmark

This page compares how much it costs to **build** agents in Bricks and in four Python agent frameworks. The figures come from the benchmark report of **8 October 2026** (`docs/benchmarks-bricks-2026-10-08.md` in the repository): Bricks 0.4.6 at commit `dee981e`, and the Python versions locked in `bench/general-agents/uv.lock`.

<Callout type="warn">
**What is not measured.** No model call is made. Each harness builds an agent with one tool and does not run a turn, so these numbers say nothing about answer quality, latency to a first token, or token cost. The figures predate the change that runs each `Bash` call in its own process (commit `4263cd9`).
</Callout>

## Construction

Mean time to build one agent, in microseconds (µs), and the memory allocated for each agent that stays alive:

| Framework | Version | Construction, mean | Allocation per agent |
|-----------|---------|-------------------:|---------------------:|
| Bricks | 0.4.6 | 21.33 µs | 71,703 bytes |
| Agno | 2.5.17 | 6.02 µs | 5,394 bytes |
| LangGraph | 1.1.8 | 1,950.65 µs | 30,344 bytes |
| PydanticAI | 1.22.0 | 228.62 µs | 8,196 bytes |
| CrewAI | 1.14.2 | 7,476.15 µs | 17,900 bytes |

Bricks allocates more per agent than the Python frameworks in this measurement, and builds faster than LangGraph, PydanticAI and CrewAI. Agno is faster and smaller here. The report measures Rust memory with jemalloc and Python memory with `tracemalloc`, which does not count every native allocation, so the allocation column is not a like-for-like RAM comparison.

## Concurrent construction

1,000 agents built concurrently and kept alive:

| Framework | Total time | Maximum process RSS |
|-----------|-----------:|--------------------:|
| Bricks | 20.43 ms | 98.5 MiB |
| Agno | 19.0 ms | 103.6 MiB |
| LangGraph | 2,101.1 ms | 168.7 MiB |
| PydanticAI | 262.1 ms | 107.2 MiB |
| CrewAI | 3,024.0 ms | 1,526.2 MiB |

The RSS includes the runtime, the imports, and the peaks of the earlier phases. The per-agent latencies are not directly comparable: the Python figures include the wait before the task starts, through `asyncio.to_thread`.

Bricks also reached **10,000 agents**: total construction 197.37 ms, maximum RSS 647.3 MiB, and per-agent construction p50 0.066 ms and p99 1.048 ms. The report calls this the largest step it tried, not a limit.

## Reproduce

Python harnesses, from `bench/general-agents`:

```bash
uv sync --locked --extra all --python 3.12
.venv/bin/python bench_agno.py
.venv/bin/python bench_langgraph.py   # same pattern for the other harnesses
```

The Rust harness is the `general_agent_bench` example of the `bricks-agent` package:

```bash
CERSEI_BENCH_AXES=1,2,3,4 cargo run --release -p bricks-agent \
  --example general_agent_bench --features bench-full
```

`CERSEI_BENCH_AXES` selects the axes; the variable keeps its name. See `bench/general-agents/README.md`.

## Earlier figures

Earlier runs of this comparison, on Bricks 0.1.6 and an Apple M1 Pro, gave different numbers (for example, a construction time of 7.12 µs for the Rust side). Those figures are superseded by the report above and are not reproduced here.
