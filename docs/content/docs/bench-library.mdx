# Library Benchmarks

These are measurements of the in-process tools, from the benchmark report of **8 October 2026** (`docs/benchmarks-bricks-2026-10-08.md` in the repository). They were taken on Bricks 0.4.6 at commit `dee981e`, on Apple A18 Pro, macOS 27.2, release build, with a standalone suite of 100 iterations after warm-up, on temporary files.

<Callout type="warn">
The report predates the change that runs each `Bash` call in its own process (commit `4263cd9`). The `Bash` row below is therefore not a measure of the current code, and the other tools are not affected by that change. Run the suite again before you compare.
</Callout>

## Tool dispatch

| Tool | Mean | Min | Max |
|------|-----:|----:|----:|
| Read | 0.118 ms | 0.111 ms | 0.378 ms |
| Write | 0.050 ms | 0.037 ms | 0.290 ms |
| Edit | 0.759 ms | 0.700 ms | 1.830 ms |
| Glob | 0.066 ms | 0.046 ms | 0.230 ms |
| Grep | 2.017 ms | 1.365 ms | 4.765 ms |
| Bash (before the per-process change) | 39.695 ms | 35.799 ms | 84.883 ms |
| `std::fs::read` (reference) | 0.010 ms | 0.010 ms | 0.012 ms |
| `std::fs::write` (reference) | 0.045 ms | 0.028 ms | 0.165 ms |

The report notes that `Edit` replaces every occurrence of a repeated text in the file, and that earlier figures timed an ambiguous call whose error was ignored. They are not comparable with these.

## Reproduce

From the repository root:

```bash
cargo run --release -p bricks --example benchmark_io
```

The other examples of the `bricks` package are `stress_tools`, `stress_memory`, `stress_skills`, `stress_orchestration` and `stress_core_infrastructure`, run the same way with `--example NAME`. The standalone suite is in `examples/benchmark`:

```bash
CARGO_PROFILE_RELEASE_OPT_LEVEL=z CARGO_PROFILE_RELEASE_LTO=thin \
  cargo run --release --manifest-path examples/benchmark/Cargo.toml
```

Results depend on the machine, the file system and what else is running. Compare runs made the same way, on the same machine.
