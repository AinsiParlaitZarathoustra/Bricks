# Cookbook: Agent Deployment

Each recipe builds an agent with the `bricks` facade. The provider comes from a `provider_id/model_id` selection in `~/.bricks/providers.toml`, so the same code works with any provider you have configured. Recipes that run without a person present use `AllowAll`, which approves every tool call. Use it only where that is what you want: a sandbox, a copy of a repository, or a task you have reviewed.

## As a command-line tool

A single binary that takes a prompt, or reads prompts from standard input:

```rust
use bricks::prelude::*;
use clap::Parser;

#[derive(Parser)]
struct Cli {
    prompt: Option<String>,
    /// provider_id/model_id, from ~/.bricks/providers.toml
    #[arg(long)]
    model: String,
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let cli = Cli::parse();

    let agent = Agent::builder()
        .provider(bricks::provider_from_config(None, &cli.model)?)
        .tools(bricks::tools::all())
        .permission_policy(AllowAll)
        .auto_compact(true)
        .build()?;

    if let Some(prompt) = cli.prompt {
        let output = agent.run(&prompt).await?;
        println!("{}", output.text());
    } else {
        use std::io::BufRead;
        for line in std::io::stdin().lock().lines() {
            let input = line?;
            if input.trim().is_empty() {
                break;
            }
            let output = agent.run(input.trim()).await?;
            println!("{}", output.text());
        }
    }
    Ok(())
}
```

`tools::all()` includes shell and file tools, so `AllowAll` lets the agent run commands in the current directory. For a read-only assistant use `tools::coding()` with the approver `DenyAll`: reads run, and writes, commands and web calls are refused.

## As an HTTP API

A route that answers each request with a new agent. It returns the errors instead of panicking:

```rust
use axum::{http::StatusCode, routing::post, Json, Router};
use bricks::prelude::*;
use serde::{Deserialize, Serialize};

#[derive(Deserialize)]
struct AgentRequest { prompt: String }

#[derive(Serialize)]
struct AgentResponse { response: String, output_tokens: u64, turns: u32 }

async fn handle(Json(req): Json<AgentRequest>) -> std::result::Result<Json<AgentResponse>, (StatusCode, String)> {
    let provider = bricks::provider_from_config(None, "my-provider/my-model")
        .map_err(|e| (StatusCode::INTERNAL_SERVER_ERROR, e.to_string()))?;

    let output = Agent::builder()
        .provider(provider)
        .tools(bricks::tools::coding())
        .permission_policy(DenyAll)
        .run_with(&req.prompt)
        .await
        .map_err(|e| (StatusCode::INTERNAL_SERVER_ERROR, e.to_string()))?;

    Ok(Json(AgentResponse {
        response: output.text().to_string(),
        output_tokens: output.usage.output_tokens,
        turns: output.turns,
    }))
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let app = Router::new().route("/agent", post(handle));
    let listener = tokio::net::TcpListener::bind("0.0.0.0:3000").await?;
    axum::serve(listener, app).await?;
    Ok(())
}
```

Building an agent per request keeps requests independent. Each one starts with no conversation history.

## With session persistence

`JsonlMemory` stores each session as JSON lines in a directory. Giving the same `session_id` to a new agent continues the conversation:

```rust
use bricks::memory::JsonlMemory;   // re-exported from bricks-memory

let agent = Agent::builder()
    .provider(bricks::provider_from_config(None, "my-provider/my-model")?)
    .tools(bricks::tools::coding())
    .memory(JsonlMemory::new("./sessions"))
    .session_id(session_id)          // impl Into<String>
    .auto_compact(true)
    .build()?;

// Run it as usual; a later process that uses the same session_id resumes the history.
```

## With structured memory

`StructuredMemory` keeps project facts and episodes in Grafeo and `usearch`, so the agent can recall them in later sessions. Its store is behind the `structured` feature of `bricks-memory`, which the `bricks` facade does not turn on. Enable it in your own `Cargo.toml`:

```toml
bricks-memory = { version = "1.0.0-alpha.1", features = ["structured"] }
bricks-embeddings = "1.0.0-alpha.1"
```

```rust
use bricks_embeddings::HashingEmbeddings;
use bricks_memory::structured::{EpisodeInput, RecallQuery, StructuredMemory, GLOBAL_SPACE};
use std::sync::Arc;
use tokio_util::sync::CancellationToken;

let memory = StructuredMemory::builder(Arc::new(HashingEmbeddings::new(384)))
    .path("./agent.db")
    .open()?;

memory
    .record(EpisodeInput {
        space: GLOBAL_SPACE.into(),
        project_id: Some("my-project".into()),
        session_id: Some("session-1".into()),
        role: "user".into(),
        author: None,
        content: "User prefers functional patterns.".into(),
        occurred_at: None,
        source_ref: None,
    })
    .await?;
memory.process(&CancellationToken::new()).await?;

let recalled = memory.recall(&RecallQuery::new("coding style preferences")).await?;
```

See [Structured Graph Memory](/docs/cookbook-graph-memory) for full details.

## Background job

A loop that runs an agent on a schedule, in a project directory:

```rust
use std::time::Duration;

loop {
    let output = Agent::builder()
        .provider(bricks::provider_from_config(None, "my-provider/my-model")?)
        .tools(bricks::tools::coding())
        .working_dir("./my-project")
        .permission_policy(AllowAll)
        .build()?
        .run("Check for new issues and fix any simple bugs")
        .await?;

    println!("agent completed: {} turns, {} tool calls", output.turns, output.tool_calls.len());
    tokio::time::sleep(Duration::from_secs(3600)).await;
}
```

Run this under a supervisor such as systemd or a container runtime, so that a crash restarts it. The loop itself has no retry logic.

## Sub-agents and orchestration

The agent builder does not add sub-agent tools by itself. `tools::all()` is `coding()` plus `TodoWrite`, and the isolation of sub-agent work is carried by `Agent` and `Agents` (`isolation`), not by a separate worktree tool. The sub-agent tools are not in `tools::all()`. The `bricks` command-line tool and desktop app add the native `Agent`, `Agents`, `AgentControl`, `AgentProfiles` and `SendMessage` tools when `[agents] enabled` is set in `bricks.toml`: those tools are backed by a spawner that the session controller creates. An agent built only with `Agent::builder()` does not get them.

```rust
let agent = Agent::builder()
    .provider(bricks::provider_from_config(None, "my-provider/my-model")?)
    .tools(bricks::tools::all())   // coding() + TodoWrite; no sub-agent tools
    .system_prompt("You are a coordinator. Split the work and check the results.")
    .build()?;
```
