# bricks-memory

`bricks-memory` provides two kinds of storage:

1. **Session storage** (`Memory` trait): saves and loads conversation transcripts (`JsonlMemory` for disk files, `InMemory` for tests).
2. **Long-term memory** (`LongTermMemory` trait, `structured` feature): stores notes, exchanges, and extracted facts in a Grafeo database (`StructuredMemory` and `ScopedMemory`), and recalls relevant context across sessions.

<Callout type="info">
Long-term structured memory is behind the `structured` feature flag (`default = []`). Enable it on `bricks-memory` directly (`bricks-memory = { features = ["structured"] }`), as the `bricks` facade does not turn it on by default.
</Callout>

## Memory and LongTermMemory Traits

```rust
use bricks_types::{MemoryEntry, SessionInfo};
use bricks_memory::{MaintenanceReport, MemoryScope, MemoryTurn, RecalledContext};
use tokio_util::sync::CancellationToken;

#[async_trait]
pub trait Memory: Send + Sync {
    async fn store(&self, session_id: &str, messages: &[Message]) -> Result<()>;
    async fn load(&self, session_id: &str) -> Result<Vec<Message>>;
    async fn search(&self, query: &str, limit: usize) -> Result<Vec<MemoryEntry>>;
    async fn sessions(&self) -> Result<Vec<SessionInfo>>;
    async fn delete(&self, session_id: &str) -> Result<()>;
    fn session_files_dir(&self, session_id: &str) -> Option<PathBuf> { None }
}

#[async_trait]
pub trait LongTermMemory: Send + Sync {
    async fn recall_context(&self, query: &str, max_tokens: usize) -> Result<Option<RecalledContext>>;
    async fn record_turns(&self, session_id: Option<&str>, turns: &[MemoryTurn]) -> Result<()>;
    async fn search(&self, scope: MemoryScope, query: &str, limit: usize) -> Result<Option<RecalledContext>>;
    async fn write_note(&self, scope: MemoryScope, session_id: Option<&str>, text: &str) -> Result<String>;
    async fn maintain(&self, cancel: &CancellationToken) -> Result<MaintenanceReport>;
}
```

- `JsonlMemory::new(dir)` persists each session as JSONL files on disk (with atomic checkpoints for active and raw histories).
- `InMemory::new()` keeps sessions in memory for tests.
- `LongTermMemory` powers cross-session recall: `record_turns` stores an exchange quickly, and `maintain` runs model extraction and embeddings later so interrupted work can resume.

## Session Storage (JSONL)

Append-only JSONL transcripts for session persistence (`bricks_memory::session_storage`).

**Entry types** (`TranscriptEntry`):

| Type | Description |
|------|-------------|
| `User` | User message with UUID, timestamp, and parent link |
| `Assistant` | Assistant message with UUID, timestamp, and parent link |
| `System` | System message |
| `Summary` | Compaction summary (replaces multiple messages) |
| `Tombstone` | Soft-delete marker (skipped on load) |

Each file part is at most 50 MB, and a session's parts total at most 200 MB. Malformed lines are skipped silently.

## Structured Long-Term Memory (`feature = "structured"`)

`StructuredMemory` stores sourced, immutable **episodes**, **entities**, and temporal **facts** (each with evidence and a status) in a Grafeo store, paired with a vector index for hybrid recall.

Recall combines three signals (vector search, lexical search, and bounded graph expansion) using weighted reciprocal rank fusion, and formats the results to fit inside a token budget.

Ingestion is resumable:
1. An episode is saved first.
2. An `Extractor` (such as `LlmExtractor`) extracts entities and facts and caches the result.
3. Embeddings are computed and the graph is updated. If a step is cancelled or fails, the episode stays pending for the next `maintain` call.

```rust
use std::sync::Arc;
use bricks_memory::structured::{MemoryConfig, StructuredMemory};

let memory = StructuredMemory::builder(embedder)   // Arc<dyn EmbeddingProvider>
    .path("./memory.grafeo")
    .config(config)                                 // e.g. MemoryConfig::from_bricks_toml(text)?
    .extractor(extractor)                           // Arc<dyn Extractor>
    .open()?;

let agent = Agent::builder()
    .provider(provider)
    .long_term_memory(Arc::new(memory))             // recall is added to the run's system prompt
    .memory_recall_tokens(1200)                     // default token budget for recalled context
    .build()?;
```

`MemoryConfig::enabled` defaults to `false`: nothing is recorded until enabled. In `bricks.toml`, these settings live under `[memory]`.

### ScopedMemory

`ScopedMemory` wraps a project store and a global store behind a single `LongTermMemory` implementation:

- **Capture** (`record_turns`) writes only to the project store when the run has a project.
- **Recall** (`recall_context`) queries both scopes, merges results by rank, and returns at most `RECALL_MAX` (`5`) entries within the token budget. Ties favor the project scope.
- **Tools**: `memory_search` and `memory_write` read and write a chosen `MemoryScope` (`Project` or `Global`).

### Notes and Entry Deletion

- Explicit notes are kept short and atomic: `NOTE_MAX_CHARS` is `280` characters. Longer notes are rejected with `NoteError::Invalid`.
- Individual entries can be removed with `delete_entry(kind, id)`, where `kind` is `EntryKind::Note`, `EntryKind::Exchange`, or `EntryKind::Fact`. Deleting a note or exchange also marks any facts that no longer have supporting evidence as unsupported.
