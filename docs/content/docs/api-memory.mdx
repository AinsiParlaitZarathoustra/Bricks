# bricks-memory

Memory backends for sessions and for knowledge that outlives a session. The `Memory` trait stores session transcripts; `MemoryManager` composes flat memory files, the CLAUDE.md hierarchy and an optional graph index (Grafeo); and the `LongTermMemory` trait, implemented by the structured store, gives an agent recall across sessions.

<Callout type="info">
Two features are compile-time options, both off by default in `bricks-memory` (`default = []`). `graph` enables the Grafeo graph index (`bricks-memory = { features = ["graph"] }`). `structured` enables the structured long-term memory (episodes, entities, temporal facts), which the `bricks` CLI turns on. The `bricks` facade declares neither feature, so enable them on `bricks-memory` directly.
</Callout>

---

## Architecture

```
Sessions        — Memory trait: JsonlMemory (files), InMemory (tests); append-only JSONL transcripts
Flat files      — memdir: Claude Code compatible .md files, scanned by MemoryManager
Instructions    — CLAUDE.md hierarchy: 4 levels, merged into one context string
Graph (optional)— GraphMemory on Grafeo (feature `graph`): indexed recall when enabled
Long-term       — LongTermMemory / StructuredMemory (feature `structured`): hybrid recall
```

When you call `MemoryManager::recall()`, the graph is queried first if it is enabled. If it returns nothing, or no graph is enabled, the flat files are scanned with text matching.

## Memory and LongTermMemory Traits

```rust
use bricks_types::{MemoryEntry, SessionInfo};
use bricks_memory::{MaintenanceReport, MemoryTurn, RecalledContext};
use tokio_util::sync::CancellationToken;
#[async_trait]
pub trait Memory: Send + Sync {
    async fn store(&self, session_id: &str, messages: &[Message]) -> Result<()>;
    async fn load(&self, session_id: &str) -> Result<Vec<Message>>;
    async fn search(&self, query: &str, limit: usize) -> Result<Vec<MemoryEntry>>;
    async fn sessions(&self) -> Result<Vec<SessionInfo>>;
    async fn delete(&self, session_id: &str) -> Result<()>;
    fn session_files_dir(&self, session_id: &str) -> Option<PathBuf> { None }
}

#[async_trait]
pub trait LongTermMemory: Send + Sync {
    async fn recall_context(&self, query: &str, max_tokens: usize) -> Result<Option<RecalledContext>>;
    async fn record_turns(&self, session_id: Option<&str>, turns: &[MemoryTurn]) -> Result<()>;
    async fn maintain(&self, cancel: &CancellationToken) -> Result<MaintenanceReport>;
}
```

`Memory` persists sessions. `JsonlMemory::new(dir)` stores them as files and `InMemory::new()` keeps them in process. `LongTermMemory` is what an agent uses across sessions: `record_turns` stores an exchange durably and quickly, and `maintain` does the model and embedding work later, resumably.

## MemoryManager

The unified interface that composes the flat files, the CLAUDE.md hierarchy and the optional graph.

```rust
use std::path::Path;
use bricks::memory::manager::MemoryManager;

let mm = MemoryManager::new(Path::new("."))
    .with_graph(Path::new("./memory.grafeo"))?;
```

### Context Building

These methods build the memory content that gets injected into the system prompt:

| Method | Returns | Description |
|--------|---------|-------------|
| `build_context()` | `String` | Full system prompt section: CLAUDE.md hierarchy + MEMORY.md index merged |
| `scan()` | `Vec<MemoryFileMeta>` | All memory files with frontmatter metadata, sorted by recency |
| `load_file(path: &Path)` | `Option<MemoryFile>` | Load a specific memory file with content (frontmatter stripped) |

```rust
// Build the complete memory context for the system prompt
let context = mm.build_context();

// Scan all memory files
for meta in mm.scan() {
    println!("{}: {} (type: {:?})", meta.filename, meta.description.unwrap_or_default(), meta.memory_type);
}
```

### Recall and Query

| Method | Returns | Description |
|--------|---------|-------------|
| `recall(query, limit)` | `Vec<String>` | Query-based recall. Graph first when enabled, text fallback over the flat files. |
| `by_type(MemoryType)` | `Vec<String>` | Filter by type (graph only, empty without graph) |
| `by_topic(topic)` | `Vec<String>` | Filter by topic tag (graph only) |

```rust
use bricks_memory::memdir::MemoryType;
// Recall: graph lookup when enabled, otherwise a text scan of the flat files
let results = mm.recall("testing preferences", 5);

// Filter by type
let user_memories = mm.by_type(MemoryType::User);

// Filter by topic
let rust_memories = mm.by_topic("rust");
```

### Graph Operations

These only work when graph is enabled. They're no-ops otherwise.

| Method | Returns | Description |
|--------|---------|-------------|
| `store_memory(content, type, confidence)` | `Option<String>` | Store a memory node. Returns its id. |
| `tag_memory(id, topic)` | `()` | Associate a memory with a topic. Creates the topic if needed. |
| `link_memories(from, to, relationship)` | `()` | Create a RELATES_TO edge between two memories. |
| `has_graph()` | `bool` | Whether graph is enabled. |
| `graph_stats()` | `GraphStats` | Counts: `memory_count`, `topic_count`, `relationship_count`, `session_count`. |

```rust
use bricks_memory::memdir::MemoryType;
// Store a memory
let id = mm.store_memory(
    "User prefers functional patterns over OOP",
    MemoryType::User,
    0.9,  // confidence, from 0.0 to 1.0
);

// Tag it
if let Some(ref id) = id {
    mm.tag_memory(id, "coding-style");
    mm.tag_memory(id, "preferences");
}

// Link two memories
mm.link_memories(&id_a, &id_b, "contradicts");
mm.link_memories(&id_c, &id_d, "extends");

// Check stats
let stats = mm.graph_stats();
println!("{} memories, {} topics, {} relationships", stats.memory_count, stats.topic_count, stats.relationship_count);
```

### Session Operations

| Method | Returns | Description |
|--------|---------|-------------|
| `write_user_message(session_id, msg)` | `io::Result<String>` | Append user message to JSONL. Returns its UUID. |
| `write_assistant_message(session_id, msg, parent)` | `io::Result<String>` | Append assistant message. `parent` is the UUID of the message it answers, if any. |
| `load_session_messages(session_id)` | `Result<Vec<Message>>` | Load all messages, applying tombstones. |
| `list_sessions()` | `Vec<SessionInfo>` | List all session files. |
| `session_path(session_id)` | `PathBuf` | Get the JSONL file path for a session. |

```rust
// Write
let user_id = mm.write_user_message("session-1", Message::user("Hello"))?;
let asst_id = mm.write_assistant_message("session-1", Message::assistant("Hi!"), Some(&user_id))?;

// Load
let messages = mm.load_session_messages("session-1")?;
assert_eq!(messages.len(), 2);
```

## Graph Schema

When the graph is enabled, the Grafeo graph stores three node types and three edge types:

```
Node Types:
  (:Memory) { id, content, mem_type, confidence, created_at, updated_at }
  (:Topic)  { name }
  (:Session) { session_id, started_at, model, turns }

Edge Types:
  (:Memory) -[:RELATES_TO { relationship, weight }]-> (:Memory)
  (:Topic)  -[:TAGGED]->                              (:Memory)
  (:Session) -[:PRODUCED]->                           (:Memory)
```

The structured long-term memory (below) uses its own store and schema.

## Memdir (Flat Files)

Compatible with Claude Code's memory directory format.

**Location:** `~/.claude/projects/<sanitized-root>/memory/`, or the path in `CERSEI_MEMORY_PATH_OVERRIDE`. `MemoryManager::with_memory_dir` sets it explicitly.

**File format:**
```markdown
---
name: Memory Title
description: One-line description for recall
type: user
---

Actual memory content here.
```

**Limits:**
- `MEMORY.md` index: max 200 lines or 25,000 bytes
- Memory files scanned: max 200, sorted newest-first
- Types: `user`, `feedback`, `project`, `reference`

## CLAUDE.md Hierarchy

Loaded in priority order (highest to lowest):

| Scope | Path | Purpose |
|-------|------|---------|
| Managed | `~/.claude/rules/*.md` | Organization rules (alphabetically sorted) |
| User | `~/.claude/CLAUDE.md` | User-level preferences |
| Project | `{root}/CLAUDE.md` | Project-level instructions |
| Local | `{root}/.claude/CLAUDE.md` | Local overrides (gitignored) |

All levels are merged into a single context string by `load_all_memory_files(project_root)`. Supports `@include <path>` directives (max depth 10, max 40KB per include, circular reference detection). Frontmatter is stripped automatically.

## Session Storage (JSONL)

Append-only JSONL transcripts compatible with Claude Code's session format.

**Entry types** (`TranscriptEntry`):

| Type | Description |
|------|-------------|
| `User` | User message with UUID, timestamp, parent link |
| `Assistant` | Assistant message with UUID, timestamp, parent link |
| `System` | System message |
| `Summary` | Compaction summary (replaces multiple messages) |
| `Tombstone` | Soft-delete marker (skipped on load) |

**Location:** `<sessions dir>/<session-id>.jsonl`. With `MemoryManager`, the default is `~/.claude/projects/<sanitized-root>/`.

Each file part is at most 50 MB, and a session's parts total at most 200 MB. Malformed lines are skipped silently.

## Auto-Dream (Background Consolidation)

`AutoDream` lives in `bricks_agent::auto_dream`. It decides whether memory consolidation is due, using three gates. Nothing in the agent runner calls it in this version; only an example does (`crates/bricks/examples/stress_memory.rs`):

| Gate | Condition | Default |
|------|-----------|---------|
| Time | Hours since last consolidation | 24 hours (`AutoDreamConfig::min_hours`) |
| Session | New sessions since last run | 5 sessions (`AutoDreamConfig::min_sessions`) |
| Lock | No concurrent consolidation | Stale after 1 hour |

All three gates must pass before consolidation is due. `AutoDream` starts nothing: the caller runs the consolidation, between `acquire_lock()` and `release_lock()`, with the prompt from `consolidation_prompt()` (`crates/bricks-agent/src/auto_dream.rs`).

```rust
use bricks_agent::auto_dream::AutoDream;

let dreamer = AutoDream::new(memory_dir, conversations_dir);  // PathBuf, PathBuf

if dreamer.should_consolidate() {
    dreamer.acquire_lock()?;
    // Run the consolidation agent with dreamer.consolidation_prompt()...
    dreamer.update_state()?;   // records the run for the time and session gates
    dreamer.release_lock()?;
}
```

## Session Memory Extraction

Extraction of memories from conversations, in `bricks_agent::session_memory`. The functions are available to callers; the agent runner does not call them in this version. Extraction is due after at least 20 messages and 3 tool calls since the last extraction (`crates/bricks-agent/src/session_memory.rs:13-14`).

**Categories extracted** (`MemoryCategory`):

| Category | Example |
|----------|---------|
| `UserPreference` | "Prefers functional patterns" |
| `ProjectFact` | "API uses REST with JSON" |
| `CodePattern` | "Uses builder pattern for config" |
| `Decision` | "Chose PostgreSQL over SQLite" |
| `Constraint` | "Must support Python 3.8+" |

```rust
use bricks_agent::session_memory;

// Check if extraction should run
if session_memory::should_extract(&messages, &state) {
    // Parse extraction output from the model
    let memories = session_memory::parse_extraction_output(&model_output);

    // Persist to memory directory
    session_memory::persist_memories(&memories, &memory_path)?;
}
```

## Structured Long-Term Memory (feature `structured`)

`StructuredMemory` implements `LongTermMemory`. It keeps sourced, immutable **episodes**, scoped **entities** and temporal **facts** (each with evidence and a status) in a Grafeo store. Recall is hybrid: vector search, lexical search and a bounded relational expansion, fused by weighted reciprocal rank fusion, and rendered within a token budget.

Ingestion is resumable. An episode is stored first; extraction (by an `Extractor`, such as `LlmExtractor`, which calls a configured model) is cached before anything is applied; a failed step leaves the episode pending for the next `maintain` pass.

```rust
use std::sync::Arc;
use bricks_memory::structured::StructuredMemory;

let memory = StructuredMemory::builder(embedder)   // Arc<dyn EmbeddingProvider>
    .path("./memory.grafeo")
    .config(config)                                 // MemoryConfig, e.g. MemoryConfig::from_bricks_toml(text)?
    .extractor(extractor)                           // Arc<dyn Extractor>
    .open()?;

let agent = Agent::builder()
    .provider(provider)
    .long_term_memory(Arc::new(memory))             // recall is added to each run's system prompt
    .memory_recall_tokens(1200)                     // default budget of the recalled context
    .build()?;
```

`MemoryConfig::enabled` defaults to `false`: nothing is recorded until it is set. In `bricks.toml`, the same settings are under `[memory]`.
