# bricks-vms — API Reference

All public types live under `bricks_vms` and are re-exported as `bricks::vms` behind the default-on `vms` feature of the `bricks` facade.

```rust
use bricks::vms::prelude::*;
// or, against the crate directly:
use bricks_vms::prelude::*;
```

## Feature flags

| Flag | Default | What it enables |
|---|---|---|
| `backend-docker` | yes | `DockerRuntime`, which shells out to the `docker` CLI. |
| `backend-firecracker` | no | Reserved. No code behind it. |
| `backend-e2b` | no | Reserved. No code behind it. |
| `envd` | yes | Builds the `cersei-envd` binary (`src/bin/cersei_envd.rs`). |

The `bricks` facade feature `vms` (default-on) enables the `vms` feature of `bricks-tools` (which adds the `vm_tools` module and the Bash routing) and re-exports the crate as `bricks::vms`.

## `SandboxRuntime`

The top-level trait. A runtime creates and lists sandboxes and owns the host-side broker (`Mailbox`, `KvStore`) and the snapshot registry of its backend.

```rust
#[async_trait]
pub trait SandboxRuntime: Send + Sync {
    fn name(&self) -> &str;                       // "local" | "docker"
    fn capabilities(&self) -> RuntimeCaps;

    async fn create(&self, opts: SandboxOpts) -> Result<SandboxHandle>;
    async fn get(&self, id: &SandboxId) -> Result<SandboxHandle>;
    async fn list(&self) -> Result<Vec<SandboxInfo>>;

    // Default: VmError::Snapshot. Both backends override it.
    async fn restore(&self, snapshot: &SnapshotId) -> Result<SandboxHandle>;
}
```

`SandboxHandle` is an alias for `Arc<dyn Sandbox>`.

### `RuntimeCaps`

```rust
pub struct RuntimeCaps {
    pub snapshots: bool,
    pub pause_resume: bool,
    pub gpu: bool,
    pub network_isolation: bool,
    pub shared_volumes: bool,
    pub remote: bool,
}
```

| Backend | `snapshots` | `pause_resume` | `network_isolation` | `shared_volumes` | `remote` | `gpu` |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| `LocalProcessRuntime` | yes | no | no | yes² | no | no |
| `DockerRuntime` | yes | no¹ | yes | yes | no | no |

¹ `DockerRuntime` implements `pause()` and `resume()` with `docker pause` and `docker unpause`, but reports `pause_resume: false`. Check the flag before relying on pause.

² The local backend reports `shared_volumes: true`, but `SandboxOpts.volumes` are recorded in the snapshot manifest and not mounted into the sandbox directory. Do not rely on a volume being visible inside a local sandbox.

### Backends

<Tabs items={['LocalProcessRuntime', 'DockerRuntime']}>
<Tab value="LocalProcessRuntime">

No isolation: the sandbox is a directory on the host, and commands run as ordinary host processes. Each sandbox owns `~/.cersei/vms/local/<sandbox_id>/rootfs/`; an absolute path inside the sandbox such as `/foo/bar` maps to `<rootfs>/foo/bar`. The `image` option is ignored.

```rust
let rt = LocalProcessRuntime::new()?;          // ~/.cersei/vms/local
let rt = LocalProcessRuntime::with_root(dir)?; // any root; used in tests
```

Use it for development and tests. It provides no protection against the commands it runs.

</Tab>
<Tab value="DockerRuntime">

Container isolation through the local `docker` CLI. Every operation is a `docker` invocation, so the runtime needs the CLI on `PATH` (or an explicit binary) and a running daemon. It adds no client library.

```rust
let rt = DockerRuntime::new()?;                              // `docker` from PATH
let rt = DockerRuntime::with_docker_bin("/opt/bin/docker")?; // explicit binary
```

Each sandbox is a container named `cersei-vm-<sandbox_id>`.

| Trait method | Docker call |
|---|---|
| `create()` | `docker create` with the labels, environment, working directory, volume and resource options, running `/bin/sh -c "tail -f /dev/null"` in the image, then `docker start` |
| `Commands::run()` | `docker exec [-w …] [-e …] <name> /bin/sh -c <command>` |
| `Commands::stream()` | the same `docker exec`, output piped |
| `Filesystem::read()` | `docker exec <name> cat <path>` |
| `Filesystem::write()` | `docker cp` into the container |
| `Filesystem::list/stat/mkdir/remove` | `docker exec <name> /bin/sh -c '…'` |
| `snapshot()` | `docker commit <name> cersei-snapshot:<snapshot_id>`, then a manifest |
| `restore(&snap)` | `create()` from the snapshot image |
| `pause()` / `resume()` | `docker pause` / `docker unpause` |
| `kill()` | `docker rm -f <name>` |

`cersei-vm-`, `cersei-snapshot` and the `cersei/sandbox-base` image name are identifiers of the runtime and of the reference image; they keep their names.

</Tab>
</Tabs>

## `Sandbox`

```rust
#[async_trait]
pub trait Sandbox: Send + Sync {
    fn id(&self) -> &SandboxId;
    fn info(&self) -> SandboxInfo;
    fn commands(&self) -> Arc<dyn Commands>;
    fn filesystem(&self) -> Arc<dyn Filesystem>;

    async fn snapshot(&self) -> Result<SnapshotId>;   // both backends
    async fn pause(&self) -> Result<()>;               // Docker only
    async fn resume(&self) -> Result<()>;              // Docker only
    async fn kill(&self) -> Result<()>;
}
```

### `SandboxOpts`

```rust
pub struct SandboxOpts {
    pub image: String,                    // default "cersei/sandbox-base:latest"
    pub workdir: Option<PathBuf>,         // default Some("/work") from Default
    pub env: HashMap<String, String>,
    pub volumes: Vec<VolumeMount>,
    pub cpu_limit: Option<f32>,           // cores; None = no limit
    pub mem_limit: Option<u64>,           // bytes; None = no limit
    pub labels: HashMap<String, String>,
    pub from_snapshot: Option<SnapshotId>,
    pub mailbox_topics: Vec<String>,
}
```

`SandboxOpts::default()` targets `cersei/sandbox-base:latest` with `/work` as working directory. The local backend records `image` in `SandboxInfo` but runs commands on the host; it does not apply `cpu_limit` or `mem_limit`.

```rust
let opts = SandboxOpts::image("alpine:3.20")
    .with_workdir("/work")
    .with_env("LANG", "C.UTF-8")
    .with_volume(VolumeMount {
        volume_id: shared.id.clone(),
        mount_path: "/shared".into(),
        read_only: false,
    })
    .with_label("bricks.task", "build");
```

### `SandboxInfo` and `SandboxStatus`

```rust
pub enum SandboxStatus { Creating, Running, Paused, Exited, Killed, Failed }

pub struct SandboxInfo {
    pub id: SandboxId,
    pub backend: String,                 // "local" | "docker"
    pub image: String,
    pub status: SandboxStatus,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub labels: HashMap<String, String>,
}
```

### `CommandStream`

A `Stream` of `StreamChunk` values, serialized with a `kind` tag:

```rust
pub enum StreamChunk {
    Started { pid: u32 },
    Stdout { data: String },
    Stderr { data: String },
    Exit { code: i32 },
    Error { message: String },
}
```

<Callout type="info">
Streams are output-only. Stdin is not forwarded to the process.
</Callout>

## `Filesystem`

```rust
#[async_trait]
pub trait Filesystem: Send + Sync {
    async fn read(&self, path: &str) -> Result<Bytes>;
    async fn write(&self, path: &str, data: &[u8]) -> Result<()>;
    async fn list(&self, path: &str, depth: u32) -> Result<Vec<FileEntry>>;
    async fn stat(&self, path: &str) -> Result<FileEntry>;
    async fn watch(&self, path: &str, recursive: bool) -> Result<WatchStream>;
    async fn mkdir(&self, path: &str, recursive: bool) -> Result<()>;
    async fn remove(&self, path: &str, recursive: bool) -> Result<()>;
    async fn upload(&self, local: &Path, remote: &str) -> Result<()>;
    async fn download(&self, remote: &str, local: &Path) -> Result<()>;
}

pub enum FileKind { File, Dir, Symlink }

pub struct FileEntry {
    pub path: PathBuf,
    pub kind: FileKind,
    pub size: u64,
    pub modified_unix_ms: i64,
}
```

`watch()` is **not implemented** on either backend: it returns a `VmError::Lifecycle` error. `FileEvent` (`Created`, `Modified`, `Removed`, `Renamed`) is defined for the day it is.

## Cross-sandbox primitives

The three primitives live on the host, inside the process that owns the runtime. Each runtime holds one `Mailbox` and one `KvStore`, reachable with `runtime.mailbox()` and `runtime.kv()`; clones share the same state. Sandboxes do not reach them from inside a container. Today they are used by host-side code: the agent-facing tools, AgentTemplate, and your own Rust code.

### `Volume` and `VolumeRegistry`

A host directory that can be mounted into several sandboxes.

```rust
pub struct Volume {
    pub id: VolumeId,
    pub label: Option<String>,
    pub host_path: PathBuf,
    pub created_at: chrono::DateTime<chrono::Utc>,
}

let reg = VolumeRegistry::default_user()?;   // ~/.cersei/vms/volumes
let shared = reg.create(Some("build-cache".into()))?;
```

Mount a volume with `SandboxOpts::with_volume(VolumeMount { volume_id, mount_path, read_only })`. `VolumeRegistry` also offers `open`, `get`, `list` and `remove(id, force)`.

### `Mailbox` and `MailboxSubscription`

Broadcast pub/sub on string topics, built on `tokio::sync::broadcast`. Delivery is at most once and nothing is persisted: a subscriber receives only the messages published after it subscribed, and a message with no live subscriber is dropped.

```rust
let mailbox = Mailbox::new();                  // or Mailbox::with_capacity(n)
let mut sub = mailbox.subscribe("workers/results");
mailbox.publish("workers/results", SandboxId::new(), serde_json::json!({ "ok": true }))?;
let env: MailboxEnvelope = sub.recv().await?;  // try_recv() does not wait
```

`publish` returns the sequence number. `MailboxEnvelope` has `topic`, `from`, `seq`, `sent_at_unix_ms` and `payload`. `topics()` lists the known topics.

### `KvStore`

A key/value map with a version per key and compare-and-swap.

```rust
let kv = KvStore::in_memory();                 // or KvStore::open(path)
let entry: KvEntry = kv.set("progress", b"42".to_vec())?;
let next = kv.cas("progress", Some(entry.version), b"43".to_vec())?;
// next is Ok(Some(entry)) when the version matched, Ok(None) when it did not.
```

`KvStore::open(path)` persists to a file: pass a real path, since `~` is not expanded by the crate. `get`, `delete`, `keys`, `len`, `is_empty`, `snapshot` and `restore` complete the surface. `KvEntry` is `{ value: Vec<u8>, version: u64, updated_at_unix_ms: i64 }`.

## Snapshots

```rust
pub struct SnapshotManifest {
    pub id: SnapshotId,
    pub backend: String,                 // "local" | "docker"
    pub fs_pointer: String,              // backend-specific, see below
    pub original_opts: SandboxOpts,
    pub volumes: Vec<VolumeMount>,
    pub kv: KvSnapshot,
    pub mailbox_topics: Vec<String>,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub labels: HashMap<String, String>,
}
```

| Backend | `fs_pointer` |
|---|---|
| `local` | A directory under `<root>/_snapshots/`, a copy of the sandbox working directory. |
| `docker` | The image tag `cersei-snapshot:<snapshot_id>` created by `docker commit`. |

Manifests are stored in `~/.cersei/vms/snapshots` by default (`SnapshotRegistry::default_user()`); `SnapshotRegistry::open(path)` chooses another directory. `list()` and `get()` read them back.

<Callout type="warn">
**KV state is runtime-wide.** A snapshot stores the runtime's whole `KvStore`, and `restore()` writes that state back into the runtime's store, so it affects every sandbox of that runtime, not only the one restored.
</Callout>

## envd protocol

`cersei-envd` (the binary of this crate, feature `envd`) is a small JSON-RPC 2.0 daemon meant to run inside a sandbox image. It listens on a Unix socket given by `CERSEI_ENVD_SOCKET`, default `/run/cersei-envd.sock`. The wire format is one JSON request per line, one response per line; several connections are accepted at once.

| Method | Params | Result |
|---|---|---|
| `ping` | `{}` | `{ "ok": true, "ts": <unix_ms> }` |
| `info` | `{}` | `{ "envd_version", "uname" }` |
| `process.run` | `RunRequest` | `RunOutput` |
| `fs.read` | `{ "path" }` | `{ "data_b64" }` |
| `fs.write` | `{ "path", "data_b64" }` | `{ "ok": true, … }` |
| `fs.list` | `{ "path", "depth" }` | `[FileEntry, …]` |
| `fs.stat` | `{ "path" }` | `FileEntry` |
| `fs.mkdir` | `{ "path", "recursive" }` | `{ "ok": true }` |
| `fs.remove` | `{ "path", "recursive" }` | `{ "ok": true }` |

`process.stream` and `process.signal` are named in the protocol but not handled: the daemon answers `unknown method`. No backend in this crate connects to the daemon; the Docker backend uses `docker exec` and `docker cp`.

Build the daemon:

```bash
cargo build -p bricks-vms --bin cersei-envd --release --features envd
```

The reference Dockerfile is `crates/bricks-vms/docker/Dockerfile`; it copies the binary to `/usr/local/bin/cersei-envd`.

## Integration with `bricks-tools`

### Transparent routing in `BashTool`

When an `Arc<dyn bricks_vms::Sandbox>` is in `ToolContext.extensions`, `Bash` runs each command in that sandbox instead of on the host. Options that need a supervised host process are refused in that case: `background`, `yield_time_ms`, `ready_pattern` and `ready_timeout`.

```rust
use bricks::tools::ToolContext;
use bricks::vms::Sandbox;
use std::sync::Arc;

let sandbox: Arc<dyn Sandbox> = runtime.create(opts).await?;
ctx.extensions.insert::<Arc<dyn Sandbox>>(sandbox);
// Bash now runs every command inside the sandbox.
```

Only `Bash` routes. `Read`, `Write`, `Edit`, `Glob`, `Grep` and the other host tools keep working on the host filesystem.

### Agent-facing tools (`bricks_tools::vm_tools`)

These five tools are compiled with the `vms` feature and are **not registered by default**. Add the ones you need to the tool list of the agent.

| Tool | Permission | Needs in `ToolContext.extensions` | Behaviour |
|---|---|---|---|
| `SendVmMessage` | `Write` | `Mailbox` | Publishes a JSON payload to a topic. The sender is the sandbox id when one is present, else `host`. |
| `RecvVmMessage` | `ReadOnly` | `Mailbox` | Waits for the next message on a topic. Default timeout 5 000 ms, maximum 60 000 ms. The subscription is created on the first call, so messages published before it are not received. |
| `SharedStateGet` | `ReadOnly` | `KvStore` | Reads a key: value, version and update time. |
| `SharedStateSet` | `Write` | `KvStore` | Writes a key; with `expected_version`, only if the version matches. |
| `SandboxSnapshot` | `Write` | `Arc<dyn Sandbox>` | Snapshots the active sandbox and returns the snapshot id. |

The extensions are read as the plain values: insert a `Mailbox` and a `KvStore` (for example `runtime.mailbox()` and `runtime.kv()`), not `Arc` wrappers.

```rust
let ext = Extensions::default();
ext.insert(runtime.mailbox());
ext.insert(runtime.kv());
```
