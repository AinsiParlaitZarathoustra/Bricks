# bricks-compression

`bricks-compression` sits between a tool's raw `execute()` result and the agent's tool-result budget (`apply_tool_result_budget`), trimming the part of every tool output that is ANSI codes, blank lines, `Compiling …` progress spam, boilerplate comments, and unchanged function bodies.

Savings are **measurable on real provider bills** — `gpt-4o-mini` billed us 29.1% fewer input tokens on a `cargo test` turn, `gemini-2.5-flash` billed 62.1% fewer on the same fixture. Full numbers with reproduction commands live on the [Compression Benchmarks](/docs/compression-benchmarks) page.

## Levels

| Level | Behaviour |
|---|---|
| `Off` | Byte-for-byte passthrough. **Default** — zero behavioural change for existing users. |
| `Minimal` | Strip ANSI, collapse blank runs, drop non-doc comments in source files. Safe for JSON/YAML/TOML (never code-stripped). |
| `Aggressive` | Minimal **+** function body stubbing for source files (keeps signatures + imports). The command rules described under [Built-in rule files](#built-in-rule-files) apply at every level above `Off`. |

## How it decides what to do

Dispatch is routed by **tool name** (case-insensitive) and, for shell-like tools, by the **program and sub-command** that ran:

```
tool name (case-insensitive)            strategy
─────────────────────────────────────── ──────────────────────────────────────────
Bash, Exec, Shell, Run, PowerShell, …   command rules (TOML), chosen by program + sub-command
Read, ReadFile, read_file, View         language-aware code filter
WebFetch, WebSearch, web_fetch, …       hard size cap only (page windows stay whole)
Fetch, Http                             ANSI strip + generic rule
everything else                         JSON summary when the output is large JSON, otherwise size-capped passthrough
```

Every call emits a structured `tracing::info!` event on the `bricks_compression` target so you can see exactly which rule fired, with before/after bytes, lines, and savings percent. More in the [Observability](#observability) section.

## Add it to your project

```toml
[dependencies]
bricks-compression = "0.6"
```

The crate is pure Rust. It depends on `bricks-types` and shared workspace crates (`regex`, `serde`, `serde_json`, `toml`, `tracing`), plus tree-sitter grammars for the code filter.

## 5-line quick start

<Tabs items={['As an SDK user', 'Directly', 'From bricks']}>
<Tab value="As an SDK user">
```rust
use bricks::Agent;
use bricks_compression::CompressionLevel;

let agent = Agent::builder()
    .provider(provider)
    .tool(my_tool)
    .compression_level(CompressionLevel::Aggressive)
    .build()?;
```

Every tool result the agent surfaces to the LLM now runs through the compression pipeline first.
</Tab>
<Tab value="Directly">
```rust
use bricks_compression::{compress_tool_output, CompressionLevel};
use serde_json::json;

let out = compress_tool_output(
    "Bash",
    &json!({"command": "cargo test"}),
    raw_stdout,
    CompressionLevel::Aggressive,
);
```

Infallible — on any internal error the raw input is returned unchanged so the agent loop never breaks.
</Tab>
<Tab value="From bricks">
```toml
# bricks.toml (project) — see docs/compression.md in the repository
[compression]
level = "aggressive"
```
</Tab>

## Agent builder knob

`AgentBuilder` takes the level directly, alongside the `.tool_result_budget()` and `.auto_compact()` setters:

```rust
use bricks_compression::CompressionLevel;

let agent = Agent::builder()
    .provider(provider)
    .tool(my_tool)
    .compression_level(CompressionLevel::Aggressive)
    .build()?;

// Runtime change — takes effect on the next tool call
agent.set_compression_level(CompressionLevel::Off);
let current = agent.compression_level();
```

The field is a shared mutex, so an embedding application can flip the active agent's level mid-session without a rebuild.

## What's in the box

| Piece | Role |
|---|---|
| `CompressionLevel` | `Off` / `Minimal` / `Aggressive` enum, parseable from string. |
| `compress_tool_output` / `Compressor::process` | Infallible entry points. `bricks-agent` calls `Compressor::process`, which also keeps the raw output so it can be read back. |
| `rules` (`RuleSet`) | The TOML rule DSL: built-in rule files plus user and `bricks.toml` layers. |
| `command` | Recognises the program and sub-command a shell line runs, to choose a rule. |
| `skeleton` | Structural skeletons of source files, extracted with tree-sitter (imports, signatures, bodies stubbed). |
| `json_view` | Structured summaries of large JSON documents. |
| `log` | Compression of command logs: diagnostics first, then rules, then budget. |
| `structured` | Machine-readable tool output (e.g. `cargo --message-format=json`) rendered back to text. |
| `raw` | `RawStore`: where the full text of a reduced output can be read back. |
| `ansi` | ANSI escape handling. |

## Built-in rule files

Eight TOML rule files are embedded at compile time (via `include_str!`). Each file holds several named rules:

| Rule file | Commands matched |
|---|---|
| `generic.toml` | Fallback for any command without a specific rule: ANSI and progress cleaned, exact repeats collapsed, diagnostics kept, the rest capped. |
| `exact.toml` | Values, file contents, search results and listings (`cat`, `head`, `tail`, `sed`, `jq`, `echo`, …): never filtered, only capped. |
| `git.toml` | `git log`, `git status`, `git clone/fetch/pull/push`, diffs and plumbing (kept as written, capped), other `git` sub-commands. |
| `rust.toml` | `cargo test` / `cargo nextest run`, `cargo build/check/clippy/doc`, `cargo run`, `cargo audit`, other `cargo` sub-commands. |
| `go.toml` | `go test`, `go build/vet/run/mod`. |
| `javascript.toml` | `npm`, `pnpm` and `yarn`: install and add commands, plus the other sub-commands. |
| `python.toml` | `pytest` / `py.test`, `uv` package commands, `pip install`, `ruff`, `mypy`. |
| `devops.toml` | `docker` (compose, build, other), `kubectl` (read, change, other). |

Rules are layered. The built-in files load first, then user files in `~/.bricks/rules/*.toml` (in byte order of their names), then the `[compression.filters.<id>]` tables of `bricks.toml`. A rule with the id of an earlier one replaces it, and `disabled = true` removes it.

## Safety net

Compression is a **pre-filter**. After it runs, `bricks-agent` still applies the tool-result budget:

- **`apply_tool_result_budget`**: when the total size of tool results crosses `tool_result_budget` (by default the model's declared input limit read as characters, about a quarter of its window, and never under 50,000), the oldest results are replaced by a placeholder that names their saved original, or says that none was saved. Results of active skills are kept.

If compression leaves a result unchanged (no rule matched, or an internal error), the budget still applies to it.

## Observability

Every call emits a single `tracing::info!` event on the `bricks_compression` target. Subscribe in your app with:

```rust
use tracing_subscriber::EnvFilter;

tracing_subscriber::fmt()
    .with_env_filter(EnvFilter::new("bricks_compression=info"))
    .init();
```

The `bricks` binary installs no subscriber of its own: `RUST_LOG` applies to binaries that install one, like the snippet above.

Sample log line from a live `gemini-2.5-flash` run:

```
INFO bricks_compression: tool-output compressed
  tool="Bash" level=aggressive strategy="shell" detail="cargo-test"
  before_bytes=2893 after_bytes=1565
  before_lines=76 after_lines=30
  savings_pct="45.9"
```

Fields emitted per call:

| Field | Meaning |
|---|---|
| `tool` | The Tool name that produced the output (`Bash`, `Read`, …). |
| `level` | `off` / `minimal` / `aggressive`. |
| `strategy` | The route taken, such as `shell`, `web` or `passthrough` (the full set is in `dispatch.rs`). |
| `detail` | Matched rule name (e.g. `cargo-test`) or detected Language (e.g. `Rust`). Empty for passthrough. |
| `before_bytes` / `after_bytes` | Raw byte counts. |
| `before_lines` / `after_lines` | Line counts. |
| `savings_pct` | Byte-level savings, formatted to one decimal place. |
