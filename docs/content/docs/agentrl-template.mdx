# AgentTemplate

**AgentTemplate** is a small language. A model writes a short program of file, network and agent operations, and Bricks ADK runs it on the existing tools. It is the programmable surface of [AgentRL](/docs/agentrl-overview): the program can be registered as a tool after it works.

It ships as the `bricks-agentlang` crate, re-exported as `bricks::agentlang` when the `agentlang` feature (or `agentrl`, which implies it) is enabled.

<Callout type="info">
**Design.** A hand-written lexer and recursive-descent parser, with no parser dependency and `line:col` positions in its errors, so a model can correct a program. Values are `serde_json::Value`. Each side-effecting builtin is checked against the permission policy, and a step budget bounds every run.
</Callout>

## A taste

```text
# variables start with $
$cfg = io.read("/etc/app.toml")
io.write("/tmp/app.toml", content: $cfg)

# chaining: the previous result is the next call's input
io.read("/tmp/in.txt").write("/tmp/out.txt")

# agents can message each other through the mailbox
$tools = agent.tools.list()
agent.send(to: "planner", $tools)

# ask whether the caller holds a permission; returns a boolean
agent.permission.ask('rw')
```

## Grammar

```text
program    = { NEWLINE } { statement ( NEWLINE | EOF ) } ;
statement  = assignment | expr ;
assignment = VAR "=" expr ;                    (* $x = ... *)
expr       = chain ;
chain      = primary { "." IDENT "(" [args] ")" } ;   (* .method(...) tails *)
primary    = call | VAR | literal | "(" expr ")" ;
call       = IDENT { "." IDENT } "(" [args] ")" ;     (* io.read, agent.tools.call *)
args       = arg { "," arg } [ "," ] ;
arg        = IDENT ":" expr  |  expr ;                 (* named or positional *)
literal    = STR | NUM | "true" | "false" | "null" | "[" [expr {"," expr}] "]" ;
```

- Variables are `$name`. Assignment is `$name = expr`.
- Strings use `'single'` or `"double"` quotes. Escapes include `\n`, `\t`, `\\`, `\"` and `\'`.
- A comment starts with `#` and runs to the end of the line.
- Statements end at a newline.

## Builtins

Each builtin maps to one tool or primitive, with a permission level that is checked before it runs.

| Call | Backend | Permission |
|---|---|---|
| `io.read($file)` | `Read` tool | read |
| `io.write($file, content: $data)` | `Write` tool | write |
| `io.edit($file, …)` | `Edit` tool | write |
| `io.glob($pattern)` | `Glob` tool | read |
| `io.grep($pattern)` | `Grep` tool | read |
| `io.delete($file)` | `Bash` (`rm`), checked as a `Bash` call | write |
| `net.get($url)` | `WebFetch` tool | read |
| `net.search($query)` | `WebSearch` tool | read |
| `agent.send(to: $id, $payload)` | `Mailbox` publish | write |
| `agent.tools.call($name, …)` | dispatch of a named tool | execute |
| `agent.tools.list()` | names of the dispatchable tools | none |
| `agent.tools.register(…)` | registration in the `bricks-agentrl` registry | dangerous |
| `agent.permission.ask(mode)`, mode `'r'`, `'w'`, `'rw'` or `'x'` | permission policy | none |
| `kv.get($key)` / `kv.set($key, $value)` | `KvStore` | read / write |

<Callout type="info">
`agent.tools.register(…)` needs a `ToolRegistry` wired into the dispatch. Without one, the call fails with a "not wired in this context" error. Nothing in the `bricks` command-line tool or desktop app wires it today.
</Callout>

### Chaining

In `io.read($src).write($dst)`, the result of each call becomes the implicit value `$_`, and it fills that tool's pipe target (for `Write`, `content`) when the call does not give it. A chain tail resolves in the namespace of its head, so `.write(...)` after `io.read(...)` is `io.write`.

## Running a program

Either call `run_program` directly, or give the agent the `RunAgentTemplate` tool, which is how an agent runs a program.

<Tabs items={['Direct', 'As an agent tool']}>
  <Tab value="Direct">
```rust
use bricks::agentlang::{EvalCtx, VecToolDispatch, run_program};
use bricks::tools::{Tool, file_read::FileReadTool, file_write::FileWriteTool};
use serde_json::json;
use std::sync::Arc;

// Dispatch resolves builtin tool names to Tool implementations.
let dispatch = Arc::new(VecToolDispatch::new(vec![
    Arc::new(FileReadTool) as Arc<dyn Tool>,
    Arc::new(FileWriteTool) as Arc<dyn Tool>,
]));

// `tool_ctx` is the ToolContext your tools run with (permissions included).
let mut ev = EvalCtx::new(&tool_ctx, dispatch)
    .with_var("src", json!("/tmp/in.txt"))
    .with_var("dst", json!("/tmp/out.txt"));

let value = run_program(
    "$data = io.read($src)\nio.write($dst, content: $data)",
    &mut ev,
).await?;
```
  </Tab>
  <Tab value="As an agent tool">
```rust
use bricks::agentlang::{DispatchHandle, RunAgentTemplateTool, VecToolDispatch};
use bricks::prelude::*;
use bricks::tools::Extensions;
use std::sync::Arc;

// The tool context needs a dispatch handle; Mailbox and KvStore are optional.
let dispatch: Arc<dyn bricks::agentlang::ToolDispatch> =
    Arc::new(VecToolDispatch::from_boxed(bricks::tools::coding()));

let ext = Extensions::default();
ext.insert(DispatchHandle(dispatch));

let agent = Agent::builder()
    .provider(bricks::provider_from_config(None, "my-provider/my-model")?)
    .tool(RunAgentTemplateTool)
    .extensions(ext)
    .build()?;
```
  </Tab>
</Tabs>

`RunAgentTemplate` takes `{ "program": string, "vars"?: object }` and is permission level `Execute`. Its programs are checked again, builtin by builtin, under the active policy.

The evaluation context:

```rust
EvalCtx::new(&tool_context, dispatch)
    .with_mailbox(Arc::new(mailbox))  // enables agent.send
    .with_kv(Arc::new(kv))            // enables kv.get / kv.set
    .with_self_id(sandbox_id)         // sender id for mailbox messages (default "agentlang")
    .with_var("x", json!(1))          // seed a variable
    .with_limits(Limits { max_steps: 1000, ..Default::default() });
```

Through `RunAgentTemplate`, the `Mailbox` and `KvStore` are read from the tool context extensions as plain values (`ext.insert(mailbox)`, `ext.insert(kv)`). If `DispatchHandle` is missing, the tool returns an error.

## Safety

- **Permission-gated.** Before a side-effecting builtin runs, the interpreter builds a `PermissionRequest` and asks the policy in the tool context. Under a read-only policy, `io.write` is refused with a `line:col` error and never reaches the tool.
- **Step budget.** `Limits::max_steps` (default 1000) bounds the number of builtin calls.
- **No host escape.** There is no `eval` or shell primitive. The host is reached only through the mapped, gated builtins.
- **Sandboxes are identities, not a jail.** If a `Sandbox` is in the context, `RunAgentTemplate` uses its id as the sender id for messages. `io.*` and `net.*` still call the host tools. Only the `Bash` tool, which `io.delete` uses, routes into a sandbox. For sandboxed work, use a `Bash`-based path or run the agent inside a sandbox you manage.

## Errors

Parse and runtime errors carry a span and read as messages a model can fix:

```text
parse error at 1:9: unterminated string literal
runtime error at 2:1: io.write: <reason from the permission policy>
```

Through `RunAgentTemplate`, these come back as an error result, so the agent sees them and can retry.

## Teaching the language to a model

`bricks::agentlang::AGENTLANG_SPEC` (or `language_spec()`) is a short, example-based description of the language. Put it in the system prompt of an agent that writes programs:

```rust
let agent = Agent::builder()
    .provider(bricks::provider_from_config(None, "my-provider/my-model")?)
    .tool(RunAgentTemplateTool)
    .append_system_prompt(bricks::agentlang::AGENTLANG_SPEC)
    .build()?;
```
