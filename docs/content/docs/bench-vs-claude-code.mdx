# Bricks against Claude Code and Codex CLI

## Current measurements (8 October 2026)

From the benchmark report `docs/benchmarks-bricks-2026-10-08.md` in the repository: 50 runs of `--version` after 3 warm-up runs, release build, Apple A18 Pro, macOS 27.2. The size is the executed file, and the memory is the maximum resident set of one run.

| CLI | Version | Mean | Min - max | Binary | Max RSS |
|---|---|---:|---:|---:|---:|
| Bricks | 0.4.6 | 4.8 ms | 4.3 - 6.1 ms | 29.4 MiB | 7.5 MiB |
| Claude Code | 2.1.289 | 7.3 ms | 6.4 - 11.2 ms | 219.0 MiB | 24.6 MiB |
| Codex CLI | 0.150.1 | 8.6 ms | 7.5 - 11.9 ms | 218.4 MiB | 16.9 MiB |

These measure starting the program, not the time to answer a prompt. The report does not measure model responses for these CLIs.

<Callout type="warn">
Bricks was measured at commit `dee981e`, before the change that runs each `Bash` call in its own process (commit `4263cd9`). Start-up and memory are not expected to depend on that change, but measure again before quoting these figures for a later build.
</Callout>

To reproduce the start-up measurement, build the release binary (for example with `cargo build --release -p bricks-cli`) and run:

```bash
python3 scripts/bench_cli.py --bricks target/release/bricks --iterations 50
```
