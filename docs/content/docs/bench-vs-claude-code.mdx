# Bricks against Claude Code and Codex CLI

## Current measurements (8 October 2026)

From the benchmark report `docs/benchmarks-bricks-2026-10-08.md` in the repository: 50 runs of `--version` after 3 warm-up runs, release build, Apple A18 Pro, macOS 27.2. The size is the executed file, and the memory is the maximum resident set of one run.

| CLI | Version | Mean | Min - max | Binary | Max RSS |
|---|---|---:|---:|---:|---:|
| Bricks | 0.4.6 | 4.8 ms | 4.3 - 6.1 ms | 29.4 MiB | 7.5 MiB |
| Claude Code | 2.1.289 | 7.3 ms | 6.4 - 11.2 ms | 219.0 MiB | 24.6 MiB |
| Codex CLI | 0.150.1 | 8.6 ms | 7.5 - 11.9 ms | 218.4 MiB | 16.9 MiB |

These measure starting the program, not the time to answer a prompt. The report does not measure model responses for these CLIs.

<Callout type="warn">
Bricks was measured at commit `dee981e`, before the change that runs each `Bash` call in its own process (commit `4263cd9`). Start-up and memory are not expected to depend on that change, but measure again before quoting these figures for a later build.
</Callout>

To reproduce the start-up measurement, build the release binary (for example with `cargo build --release -p bricks-cli`) and run:

```bash
python3 scripts/bench_cli.py --bricks target/release/bricks --iterations 50
```

## Historical comparison (Cersei era, not reproduced)

The tables below were recorded for the `abstract` CLI of the Cersei era (v0.1.0), against Claude Code v2.0.76 and Codex CLI v0.118.0. They are kept as history. They do not describe Bricks, the versions above, or the current scripts, and the record gives no date. Do not compare them with the current measurements.

### Infrastructure (historical)

| Metric | Abstract | Claude Code | Codex CLI |
|--------|----------|-------------|-----------|
| Startup | 22ms | 266ms | 57ms |
| Binary / package | 6.0 MB | 174 MB | ~15 MB |
| Peak RSS | 4.7 MB | 333 MB | 44.7 MB |
| `--help` latency | 20ms | 263ms | 57ms |
| Tool dispatch (Read) | 0.09ms | ~265ms (fork) | — |

### Memory (historical)

| Operation | Abstract | Claude Code | Codex CLI |
|-----------|----------|-------------|-----------|
| Memory recall (agent) | 98us (graph) | 7545ms (Sonnet) | 5751ms (GPT) |
| Memory write (agent) | 28us (graph) | 20687ms | 5882ms |
| Memory recall (file I/O) | 1.3ms (text) | 17.5ms (grep) | — |
| MEMORY.md load | 9.6us | 17.1ms | — |
| File scan (100 files) | 1.2ms | 26.6ms | — |
| Session parse (20K lines) | ~53ms | 378.7ms | — |

Claude Code calls Sonnet on each turn to rank which memory files are relevant. Codex runs the full agent pipeline for memory operations. The Abstract figures come from a graph lookup, with no LLM call.

### Agentic throughput (historical)

| Metric | Abstract | Claude Code | Codex CLI |
|--------|----------|-------------|-----------|
| Simple prompt ("say OK") | 2122ms | 8942ms | 3843ms |
| Sequential (10 prompts) | 1564ms/req | 12079ms/req | 4152ms/req |

Abstract and Codex both used OpenAI models, and Claude Code used Anthropic Opus through a Max plan.

### Token consumption (historical)

| Factor | Abstract | Claude Code | Codex CLI |
|--------|----------|-------------|-----------|
| System prompt | ~2200 tokens | ~8000+ tokens | ~10000+ tokens |
| Tool definitions | 34 tools | ~40 tools | ~30 tools |
| "say OK" total tokens | — | — | 10180 |
| LLM call for recall | No | Yes (Sonnet) | Yes (GPT) |

### Summary (historical)

| Category | Abstract | Claude Code | Codex CLI |
|----------|----------|-------------|-----------|
| Startup | 22ms | 266ms (12x) | 57ms (2.6x) |
| RSS | 4.7 MB | 333 MB (71x) | 44.7 MB (9.5x) |
| Simple prompt | 2122ms | 8942ms (4.2x) | 3843ms (1.8x) |
| Throughput | 1564ms/req | 12079ms/req (7.7x) | 4152ms/req (2.7x) |
| Memory recall | 98us | 7545ms | 5751ms |
| Memory write | 28us | 20687ms | 5882ms |

Ratios in parentheses are relative to Abstract.

The scripts that produced these tables, `run_tool_bench_claude.sh` and `run_tool_bench_codex.sh` in `scripts/`, still target the `abstract` binary. The full report of that comparison was kept in the `abstract-cli` crate, which is not part of this workspace.
