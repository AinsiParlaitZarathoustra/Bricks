> **Historical (Cersei era).** This page describes the old provider system
> (`from_model_string`, `--model` aliases, provider-specific environment
> variables) and the `abstract` CLI. None of it exists in Bricks: models are
> declared in `providers.toml` and chosen as `provider_id/model_id`. The
> current contract is `docs/providers.md` in the repository; do not follow
> the commands below.


# Providers

Bricks has no built-in providers. Which providers and models exist is decided by one configuration file, `~/.bricks/providers.toml` (or any explicit `.toml` or `.json` path), and a model is always selected explicitly as `provider_id/model_id`. Adding a provider, or a model that speaks one of the three supported wire protocols (`chat_completions`, `responses`, `anthropic_messages`), is a configuration change: no code and no recompilation.

<Callout type="info">
Beyond text, messages can carry **images, video, audio, and PDFs**. See [Multimodal Input](/docs/multimodal) for the file-passing API and which media each provider accepts.
</Callout>

## Selecting a Model

```
provider_id/model_id
```

The string is split at the first `/`, so model ids may contain `/`. The provider is never inferred from the model name: a bare model name is an error. Pass the selection to the agent with `provider_from_config`:

```rust
use cersei::prelude::*;

let provider = cersei::provider_from_config(None, "my-provider/my-model")?; // ~/.bricks/providers.toml
let agent = Agent::builder()
    .provider(provider)
    .tools(cersei::tools::coding())
    .build()?;
```

`None` reads `~/.bricks/providers.toml`; an explicit path replaces it. In the `bricks` CLI the same selection is given with `--model`, and the file with `--providers`:

```bash
bricks --model my-provider/my-model run "fix the tests"
bricks --providers ./providers.toml --model my-provider/my-model run "fix the tests"
```

## Reading the Configuration

```rust
use cersei::provider::ProviderRegistry;

let registry = ProviderRegistry::load(None)?;             // ~/.bricks/providers.toml
for model in registry.models() {
    println!("{}", model.selection());                    // every provider_id/model_id, in file order
}

let resolved = registry.resolve("my-provider/my-model")?;
let provider = resolved.build_provider()?;                 // reads api_key_env now
```

## Historical Catalogue (Cersei era)

<Callout type="warn">
The sections from here to [Adding Custom Providers](#adding-custom-providers) describe the built-in providers of the Cersei SDK: their default endpoints, the environment variables the old system read, and `abstract --model` commands. Bricks reads none of this, and the commands are not Bricks commands. To use one of these services today, write a `providers.toml` entry as shown in [Adding Custom Providers](#adding-custom-providers), with its `endpoint`, its `protocol` and an `api_key_env` naming the variable that holds the key.
</Callout>

## Anthropic

Claude models. Uses Anthropic's native API format (different from OpenAI).

| | |
|---|---|
| API Base | `https://api.anthropic.com` |
| Env Var | `ANTHROPIC_API_KEY` or `ANTHROPIC_KEY` |
| Format | Anthropic (native) |
| Default Model | `claude-sonnet-4-6` |

**Models:**

| Model | Context Window | Vision | Thinking | Tool Use |
|-------|---------------|--------|----------|----------|
| `claude-opus-4-6` | 200K | Yes | Yes | Yes |
| `claude-sonnet-4-6` | 200K | Yes | Yes | Yes |
| `claude-haiku-4-5` | 200K | Yes | No | Yes |

```bash
export ANTHROPIC_API_KEY=sk-ant-...
abstract "fix the tests" --model anthropic/claude-sonnet-4-6
abstract "fix the tests" --model sonnet   # alias
```

```rust
let (provider, model) = from_model_string("anthropic/claude-sonnet-4-6")?;
```

## DeepSeek

DeepSeek Chat, Reasoner, and Coder models via DeepSeek's native endpoint.

| | |
|---|---|
| API Base | `https://api.deepseek.com/v1` |
| Env Var | `DEEPSEEK_API_KEY` (the only variable required) |
| Format | OpenAI-compatible |
| Default Model | `deepseek-chat` |

**Models:**

| Model | Context Window |
|-------|---------------|
| `deepseek-chat` | 64K |
| `deepseek-reasoner` | 64K |
| `deepseek-coder` | 64K |

Minimal working example:

```bash
export DEEPSEEK_API_KEY=sk-...
abstract --provider deepseek --model deepseek-chat
abstract --provider deepseek --model deepseek-reasoner

# Equivalent model-string forms:
abstract "fix the tests" --model deepseek/deepseek-chat
abstract "fix the tests" --model deepseek            # alias → deepseek/deepseek-chat
```

Selecting `--provider deepseek` (or any `deepseek-*` model name) always resolves
`DEEPSEEK_API_KEY` and the native DeepSeek base URL — it never falls back to the
OpenAI endpoint. To point DeepSeek at a proxy/gateway instead, set
`DEEPSEEK_BASE_URL` (see [Custom Endpoints](#adding-custom-providers)).

## Auto-Detection and Aliases (removed)

Bricks does not detect a provider from a model name and has no model aliases. The prefix table and the alias table of the Cersei CLI no longer apply: every model is selected as `provider_id/model_id`.

## Adding Custom Providers

Any service that speaks one of the three protocols is added in `~/.bricks/providers.toml`, not in code. This example registers a local Ollama server, which needs no key:

```toml
schema_version = 1

[[providers]]
id = "ollama"
name = "Ollama"
endpoint = "http://localhost:11434/v1"
protocol = "chat_completions"
auth = "none"

[[providers.models]]
id = "llama"
name = "Llama 3.1 70B"
api_model = "llama3.1:70b"
streaming = true
tool_calls = true

[providers.models.limits]
max_input_tokens = 32000
max_output_tokens = 8000
```

```rust
let provider = cersei::provider_from_config(None, "ollama/llama")?;
```

For a hosted service, use `auth = "bearer"` and `api_key_env = "MY_SERVICE_API_KEY"`: the value of `api_key_env` is the name of the environment variable, never the key itself. The base URL belongs in `endpoint`. The `<PROVIDER>_BASE_URL` and `<PROVIDER>_API_KEY` variables that the old system read implicitly are no longer used. Every field is described in `docs/providers.md` in the repository, and an annotated example is in `docs/providers.example.toml`.
