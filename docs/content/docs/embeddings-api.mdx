# bricks-embeddings API

Complete public surface. Every item here is re-exported from the crate root.

---

## `EmbeddingProvider`

The single trait every embedding backend implements.

```rust
#[async_trait]
pub trait EmbeddingProvider: Send + Sync {
    fn name(&self) -> &str;
    fn dimensions(&self) -> usize;
    fn model_id(&self) -> String;   // identifies the vector space, e.g. "openai/text-embedding-3-small:1536"
    async fn embed(&self, text: &str) -> Result<Vec<f32>, EmbeddingError>;
    async fn embed_batch(&self, texts: &[String]) -> Result<Vec<Vec<f32>>, EmbeddingError>;
}
```

| Method | Description |
|---|---|
| `name()` | Short identifier (`"openai"`, `"gemini"`, …) — handy for logging. |
| `dimensions()` | Vector width. Used by `VectorIndex` to size the HNSW graph. |
| `model_id()` | Identifies the vector space. Vectors from two different ids must not be compared. The default is `name:dimensions`. The index does not store it. |
| `embed(text)` | Embed one string. Default impl calls `embed_batch(&[text])`. |
| `embed_batch(texts)` | Embed many. Implementors handle provider-specific batch limits. |

<Callout type="info">
Implementing your own provider takes ~30 lines. See the [cookbook](/docs/embeddings-cookbook#writing-a-custom-provider).
</Callout>

## `GeminiEmbeddings`

Google Gemini embeddings. Default model `gemini-embedding-001`, 3072 dimensions. Each text is sent in its own `embedContent` request, with at most 20 requests in flight and up to six attempts for transient errors (backoff from 500 ms). Text is truncated to 2000 characters. The key is sent in the `x-goog-api-key` header, not in the URL.

```rust
use bricks_embeddings::GeminiEmbeddings;

// Explicit key
let provider = GeminiEmbeddings::new("AIza...");

// From GOOGLE_API_KEY or GEMINI_API_KEY
let provider = GeminiEmbeddings::from_env()?;

// Request a smaller vector (sent as outputDimensionality).
let provider = GeminiEmbeddings::from_env()?
    .with_dimensions(768)
    .with_truncate_chars(4000);
```

## `OpenAiEmbeddings`

OpenAI (and OpenAI-compatible) embeddings. Default model `text-embedding-3-small` (1536 dimensions), base URL `https://api.openai.com/v1`, per-text truncation at 2000. A batch is sent as one request.

```rust
use bricks_embeddings::OpenAiEmbeddings;

// From OPENAI_API_KEY
let provider = OpenAiEmbeddings::from_env()?;

// Azure OpenAI / Ollama / any compatible endpoint
let provider = OpenAiEmbeddings::new("sk-...")
    .with_base_url("http://localhost:11434/v1")
    .with_model("nomic-embed-text")
    .with_dimensions(768);
```

## `VectorIndex`

Thin `usearch::Index` wrapper. HNSW approximate nearest-neighbor search with a configurable metric.

```rust
use bricks_embeddings::{VectorIndex, Metric};

let index = VectorIndex::new(1536, Metric::Cosine)?;
index.reserve(1_000)?;
index.add(42, &my_embedding)?;

let hits = index.search(&query_embedding, 10)?;
for hit in hits {
    println!("key={} sim={:.3} dist={:.3}", hit.key, hit.similarity, hit.distance);
}
```

### One-shot construction from a batch of pre-computed embeddings

```rust
let vectors: Vec<Vec<f32>> = /* ... */;
let index = VectorIndex::from_vectors(&vectors, Metric::Cosine)?;
// Keys are 0..vectors.len()
```

`VectorIndex` also has `search_filtered` (k-NN among the keys a predicate accepts, applied during the graph search), `remove(key)`, `contains(key)`, `capacity()` and `is_empty()`. The index is in memory: it is not saved to disk by this crate.

### `Metric`

```rust
pub enum Metric { Cosine, L2, InnerProduct }
```

| Metric | `usearch` kind | `similarity` formula |
|---|---|---|
| `Cosine` | `Cos` | `1.0 - distance` |
| `L2` | `L2sq` | `1.0 / (1.0 + distance)` |
| `InnerProduct` | `IP` | `distance` (already a similarity) |

### `SearchHit`

```rust
pub struct SearchHit {
    pub key: u64,
    pub distance: f32,
    pub similarity: f32,
}
```

## `EmbeddingStore<P>`

Provider + index bundled together. Use it when the "add text → search by text" flow is all you need.

```rust
use bricks_embeddings::{EmbeddingStore, OpenAiEmbeddings, Metric};

let store = EmbeddingStore::new(OpenAiEmbeddings::from_env()?, Metric::Cosine)?;

store.add_batch(&[
    (1, "doc one text".into()),
    (2, "doc two text".into()),
]).await?;

let hits = store.search("query text", 5).await?;
```

## `HashingEmbeddings`

A deterministic, local embedder: feature hashing of words and word pairs. It needs no network and no key, and gives the same vector for the same text on every machine, which suits tests, offline use and reproducible runs. It is **lexical**: two texts are close only when they share words. Do not read its results as those of a trained model.

```rust
use bricks_embeddings::{HashingEmbeddings, EmbeddingProvider};

let provider = HashingEmbeddings::new(384);      // dimensions
let vector: Vec<f32> = provider.embed_sync("some text");
```

`Bricks` uses it as the default for long-term memory (`[memory] embeddings = "hashing"`).

## `auto_from_model`

Construct a provider by inferring the family from an LLM model string.

```rust
let provider: Box<dyn EmbeddingProvider> =
    bricks_embeddings::auto_from_model("openai/gpt-4o")?;
```

The OpenAI rules are checked first, then the Gemini rule:

| Model string | Provider | Env var(s) |
|---|---|---|
| starts with `gpt`, `o1` or `o3`, or contains `openai` | `OpenAiEmbeddings` | `OPENAI_API_KEY` |
| contains `gemini` or `google` | `GeminiEmbeddings` | `GOOGLE_API_KEY`, else `GEMINI_API_KEY` |
| anything else | `OpenAiEmbeddings` (default) | `OPENAI_API_KEY` |

Returns `EmbeddingError::Config` if the relevant key is missing or empty.

## `EmbeddingError`

```rust
pub enum EmbeddingError {
    Http(reqwest::Error),   // transport failure
    Api(String),            // non-2xx from the API
    Parse(String),          // malformed response
    Index(String),          // usearch operation failed
    Config(String),         // missing / invalid configuration
}
```

Implements `std::error::Error` via `thiserror` and `From<reqwest::Error>` for `?` ergonomics.
