# AgentRL Cookbook

Recipes built on `bricks-agentrl`. They assume the `agentrl` feature of the facade:

```toml
[dependencies]
bricks = { version = "0.6", features = ["agentrl"] }
tokio = { version = "1", features = ["full"] }
anyhow = "1"
```

Each recipe reads its model from `~/.bricks/providers.toml`, as a `provider_id/model_id` selection. Replace `my_provider/my-model` with a selection that exists in your file. Run the recipes on a copy of the project: the general agent writes to its working directory without asking.

## 1. A verified coding task

Give AgentRL a task and an independent check. It tries the task, and if the general run passes, it returns `Directly`.

```rust
use bricks::agentrl::{CerseiRunner, CommandVerifier, Orchestrator, ToolRegistry, Verifier};
use bricks::provider::Provider;
use bricks::ProviderRegistry;
use std::sync::Arc;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let registry = ToolRegistry::open(dirs::home_dir().unwrap().join(".cersei/agentrl"))?;

    let verifier: Arc<dyn Verifier> = Arc::new(CommandVerifier::new(
        "python3 gcd.py 48 36 | grep -qx 12 && python3 gcd.py 0 7 | grep -qx 7",
    ));

    let model = ProviderRegistry::load(None)?.resolve("my_provider/my-model")?;
    let selection = model.selection();
    let provider_factory = Arc::new(move || {
        model.build_provider().expect("provider builds").into_boxed() as Box<dyn Provider>
    });

    let runner = Arc::new(
        CerseiRunner::new(provider_factory, "./work", registry.clone(), verifier)
            .with_model(&selection),
    );

    let orchestrator = Orchestrator::new(runner, registry.clone());
    let outcome = orchestrator
        .solve("Create gcd.py: two int args, print their GCD (Euclidean). gcd(0, n) == n.")
        .await?;

    println!("solved={} how={:?}", outcome.solved, outcome.how);
    println!("registry now has {} tool(s)", registry.len());
    Ok(())
}
```

<Callout type="warn">
The verifier must check behaviour the agent cannot rewrite. A test file that the agent can create or edit proves nothing.
</Callout>

## 2. Force the recovery loop and register a tool

The general agent often solves easy tasks on its own. To exercise the path **plan → proposals → promote → register**, give the general agent only a read tool. It usually cannot finish the task, so the verifier fails and the planner takes over. Proposals still get the full coding tools, each in its own copy of the working directory.

```rust
use bricks::agentrl::{CerseiRunner, Orchestrator, OrchestratorConfig, Solved, ToolsFactory};
use bricks::tools::{Tool, file_read::FileReadTool};
use std::sync::Arc;

let readonly: ToolsFactory = Arc::new(|| {
    vec![Box::new(FileReadTool) as Box<dyn Tool>]
});

let runner = Arc::new(
    CerseiRunner::new(provider_factory, "./work", registry.clone(), verifier)
        .with_model(&selection)
        .with_general_tools(readonly),
);

let orchestrator = Orchestrator::new(runner, registry.clone()).with_config(OrchestratorConfig {
    max_rl_rounds: 1,
    num_proposals: 2,
    session_id: "recovery".into(),
    ..Default::default()
});

let outcome = orchestrator.solve(task).await?;
if let Some(Solved::ByNewTool(id)) = &outcome.how {
    println!("registered tool {id}");
}
for e in registry.all() {
    println!("registry: {} ({})", e.name, e.tool_id);
}
```

To run the same recipe against a real model as a test, the crate ships `crates/bricks-agentrl/tests/live_agentrl.rs`. It is ignored by default and needs a model:

```bash
BRICKS_LIVE_MODEL=provider_id/model_id \
  cargo test -p bricks-agentrl --test live_agentrl -- --ignored --nocapture
```

`BRICKS_LIVE_CONFIG` names a providers file other than `~/.bricks/providers.toml`. The test pays for the model calls it makes.

## 3. The cache hit

After a tool is registered, a similar task can be solved by recalling it. `registry.search` surfaces the tool, and the general agent uses it.

```rust
let again = orchestrator.solve("fix the parser build error").await?;
match again.how {
    Some(Solved::ByCachedTool(id)) => println!("solved with registered tool {id}"),
    other => println!("path: {other:?}"),
}
```

Pass a memory to record each new tool as a recall hint:

```rust
let orchestrator = Orchestrator::new(runner, registry).with_memory(memory); // Arc<dyn Memory>
```

## 4. A custom verifier

Any type that implements `Verifier` can decide success: run a test suite, start a server and call it, compare output.

```rust
use async_trait::async_trait;
use bricks::agentrl::{VerifyResult, Verifier};
use std::path::Path;

struct CargoTestVerifier;

#[async_trait]
impl Verifier for CargoTestVerifier {
    async fn verify(&self, workdir: &Path) -> VerifyResult {
        match tokio::process::Command::new("cargo")
            .arg("test")
            .current_dir(workdir)
            .output()
            .await
        {
            Ok(o) => VerifyResult {
                passed: o.status.success(),
                detail: String::from_utf8_lossy(&o.stderr).chars().take(800).collect(),
            },
            Err(e) => VerifyResult { passed: false, detail: e.to_string() },
        }
    }
}
```

`CommandVerifier::new("cargo test")` does the same through `/bin/sh`. Write your own when you need more than an exit status.

## 5. A custom runner

The loop is generic over `AgentRlRunner`. A custom runner can use its own agents, its own proposal execution, and its own promotion.

```rust
use async_trait::async_trait;
use bricks::agentrl::{AgentRlRunner, FailureTrace, GeneralResult, Proposal, ProposalOutcome, RegistryEntry};

struct MyRunner { /* providers, sandbox runtime, … */ }

#[async_trait]
impl AgentRlRunner for MyRunner {
    async fn run_general(&self, task: &str, available: &[RegistryEntry]) -> GeneralResult { /* … */ todo!() }
    async fn plan(&self, trace: &FailureTrace, n: usize) -> Vec<Proposal> { /* … */ todo!() }
    async fn run_proposal(&self, p: &Proposal) -> ProposalOutcome { /* … */ todo!() }
    async fn promote(&self, winner: &ProposalOutcome) { /* copy or restore the winner */ }
}
```

The `todo!()` placeholders are for you to replace. Test the loop policy (registration, reuse, round limits) with a mock runner, as `crates/bricks-agentrl/tests/rl_loop.rs` does: it needs no network.

## 6. Run proposals in sandboxes

`CerseiRunner` runs each proposal in a copy of the working directory. For container isolation, write a runner whose `run_proposal` creates a sandbox, and whose `promote` copies the result out. The sandbox pieces are in [`bricks-vms`](/docs/vms-overview).

```rust
use bricks::vms::prelude::*;
use std::sync::Arc;

let runtime = DockerRuntime::new()?;                     // needs a running Docker daemon
let sb: Arc<dyn Sandbox> = runtime
    .create(SandboxOpts::image("cersei/sandbox-base:latest"))
    .await?;

// Inside run_proposal: insert `sb` into the proposal agent's extensions, so its Bash
// calls run in the container, then verify with the same Verifier as the general run.
// After a pass, the container's state can be captured with sb.snapshot().await?.
```

<Callout type="info">
This is a sketch of the wiring, not a finished runner. The sandbox is not created for the proposal by `CerseiRunner`, and nothing in the repository connects the two.
</Callout>

## 7. Author a tool from an AgentTemplate program

A model writes a short [AgentTemplate](/docs/agentrl-template) program, and the `RunAgentTemplate` tool runs it. Once the program works, it can be registered; registration by the program needs the registry wired into the dispatch, which the default setup does not do.

```rust
use bricks::agentlang::{AGENTLANG_SPEC, DispatchHandle, RunAgentTemplateTool, VecToolDispatch};
use bricks::prelude::*;
use bricks::tools::Extensions;
use std::sync::Arc;

let dispatch: Arc<dyn bricks::agentlang::ToolDispatch> =
    Arc::new(VecToolDispatch::from_boxed(bricks::tools::coding()));
let ext = Extensions::default();
ext.insert(DispatchHandle(dispatch));

let agent = Agent::builder()
    .provider(bricks::provider_from_config(None, "my-provider/my-model")?)
    .tool(RunAgentTemplateTool)
    .append_system_prompt(AGENTLANG_SPEC)  // teach the model the language
    .extensions(ext)                       // carries DispatchHandle
    .build()?;

let output = agent
    .run("Write a template that reads config.json and reports its keys.")
    .await?;
println!("{}", output.text());
```
