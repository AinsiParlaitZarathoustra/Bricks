# Multimodal Input

Messages aren't text-only. A user message can carry **images, audio, video and documents (PDF or text)** alongside text. Bricks serializes each block to the wire format of the protocol the model uses, and what a model accepts is declared in its `providers.toml` entry (`input_modalities`, `document_mime_types`).

A request that needs an input its model or adapter cannot carry fails with `Unsupported`, naming the model and the block, before anything is sent. Nothing is dropped or converted to text without saying so.

| Input | `chat_completions` | `responses` | `anthropic_messages` |
| --- | --- | --- | --- |
| Images | data, URL | data, URL, file id | data, URL, file id |
| Audio | data (`wav`, `mp3`) | no | no |
| Video | no | no | no |
| Documents | data, file id | data, URL, file id | data (`application/pdf`, `text/plain`), URL, file id |

Model-native output is text only. Media inside a tool result is carried by `anthropic_messages` (images, documents) only. See `docs/providers.md`, section 7, for the authoritative matrix.

## Attach a file in one line

`ContentBlock::from_path` reads the file, **detects its MIME type** from the leading bytes (with an extension fallback), base64-encodes it, and picks the right block type — an `Image` block for image/video/audio, a `Document` block for PDF/text.

```rust
use bricks::prelude::*;

// text + several local files
let msg = Message::user_with_files(
    "Describe what you see and how to rebuild this layout in React.",
    &["diagram.png", "screen-recording.mp4"],
)?;
```

Everything here is re-exported through `bricks::prelude`.

## Lower-level constructors

When you already hold bytes, base64, or a URL — or want to set the MIME type explicitly — use the block constructors directly:

```rust
// Images
ContentBlock::from_path("photo.jpg")?;             // read + sniff + encode
ContentBlock::image_bytes("image/png", &bytes);    // raw bytes you hold
ContentBlock::image_base64("image/png", b64_str);  // already base64
ContentBlock::image_url("https://example.com/cat.jpg");

// Documents (PDF, text, …)
ContentBlock::document_bytes("application/pdf", &pdf_bytes);
ContentBlock::document_url("https://example.com/report.pdf");

// Explicit type, auto-routed to Image vs Document by MIME kind
ContentBlock::media_bytes("video/mp4", &clip_bytes);

// Build the message
let msg = Message::user_with_media("Caption", vec![
    ContentBlock::from_path("a.png")?,
    ContentBlock::image_url("https://example.com/b.png"),
]);
```

### MIME detection

`detect_mime` is exported if you want the classifier on its own. It sniffs magic bytes for the formats the major providers accept (PNG, JPEG, GIF, WebP, PDF, MP4/MOV, WebM, MP3, WAV, Ogg) and falls back to the file extension:

```rust
use bricks::types::{detect_mime, MediaKind};

let mime = detect_mime(&bytes, Some(std::path::Path::new("clip.mp4"))); // Some("video/mp4")
let kind = MediaKind::from_mime("video/mp4");                            // MediaKind::Video
```

If the type can't be determined, `from_path` returns `CerseiError::Config` — pass the MIME explicitly via `media_bytes` in that case.

## Sending it

Multimodal messages flow through the normal request path — no special call:

```rust
use bricks::prelude::*;
use bricks::provider::{CompletionRequest, Provider, ProviderOptions};

let image = ContentBlock::from_path("demo.png")?;
let message = Message::user_with_media("What UI is this?", vec![image]);

// A model of your providers.toml that declares image input; its key comes from its api_key_env.
let provider = bricks::provider_from_config(None, "my-provider/my-vision-model")?;
let request = CompletionRequest {
    model: provider.model().api_model.clone(),
    messages: vec![message],
    system: Some("You are a careful visual analyst.".into()),
    tools: Vec::new(),
    max_tokens: 4096,
    temperature: None,
    stop_sequences: Vec::new(),
    options: ProviderOptions::default(),
    output_modalities: Vec::new(), // empty: text only
};

let response = provider.complete(request).await?.collect().await?;
println!("{}", response.message.get_all_text());
```

The same message also works through the `Agent` runner via `AgentBuilder::with_messages`.


## Runnable examples

- `crates/bricks/examples/multimodal.rs` — takes a `provider_id/model_id` and one or more files (image, audio, PDF), and sends them to that configured model.

```bash
set -a; source .env; set +a
cargo run --example multimodal -- diagram.png clip.mp4
```
