# Cookbook: Embedding Agents

These recipes call the `bricks` facade. The provider is named by a `provider_id/model_id` selection in `~/.bricks/providers.toml`; `my-provider/my-model` below stands for one of yours.

## In a Tauri desktop app

A Tauri command that answers a prompt with read-only filesystem tools:

```rust
use bricks::prelude::*;
use bricks::tools::filesystem;

#[tauri::command]
async fn ask_agent(prompt: String) -> std::result::Result<String, String> {
    let provider = bricks::provider_from_config(None, "my-provider/my-model")
        .map_err(|e| e.to_string())?;

    let output = Agent::builder()
        .provider(provider)
        .tools(filesystem())
        .permission_policy(AllowReadOnly)
        .run_with(&prompt)
        .await
        .map_err(|e| e.to_string())?;

    Ok(output.text().to_string())
}
```

## In an Actix-web server

The state keeps the selection, not a provider: each request builds its own provider, so no state is shared between requests.

```rust
use actix_web::{web, App, HttpResponse, HttpServer};
use bricks::prelude::*;

struct AppState {
    selection: String,   // "provider_id/model_id"
}

async fn agent_endpoint(
    body: web::Json<serde_json::Value>,
    state: web::Data<AppState>,
) -> HttpResponse {
    let prompt = body["prompt"].as_str().unwrap_or("");
    let provider = match bricks::provider_from_config(None, &state.selection) {
        Ok(p) => p,
        Err(e) => return HttpResponse::InternalServerError().json(serde_json::json!({ "error": e.to_string() })),
    };

    let output = Agent::builder()
        .provider(provider)
        .tools(bricks::tools::coding())
        .permission_policy(AllowReadOnly)
        .run_with(prompt)
        .await;

    match output {
        Ok(o) => HttpResponse::Ok().json(serde_json::json!({ "response": o.text() })),
        Err(e) => HttpResponse::InternalServerError().json(serde_json::json!({ "error": e.to_string() })),
    }
}
```

## Streaming events to a WebSocket

`enable_broadcast(capacity)` before `build()` makes the agent publish its events. `subscribe()` returns a receiver, or `None` when broadcast is not enabled.

```rust
let agent = Agent::builder()
    .provider(bricks::provider_from_config(None, "my-provider/my-model")?)
    .tools(bricks::tools::coding())
    .enable_broadcast(256)
    .build()?;

let mut rx = agent.subscribe().expect("broadcast is enabled");

// Forward events to the client. `ws_send` stands for your WebSocket write.
tokio::spawn(async move {
    while let Ok(event) = rx.recv().await {
        match event {
            AgentEvent::TextDelta(t) => ws_send(&t).await,
            AgentEvent::ToolStart { name, .. } => ws_send(&format!("[{name}]")).await,
            AgentEvent::Complete(_) => break,
            _ => {}
        }
    }
});

agent.run("Fix the tests").await?;
```

## A custom memory backend

`Memory` is the trait behind conversation storage. Five methods are required: `store`, `load`, `search`, `sessions` and `delete`. The others have defaults. The sketch below stores each session as one JSON document in PostgreSQL (`sqlx`), and leaves `search` and `sessions` to you.

```rust
use async_trait::async_trait;
use bricks::memory::Memory;
use bricks::types::{Message, Result};

struct PostgresMemory { pool: sqlx::PgPool }

#[async_trait]
impl Memory for PostgresMemory {
    async fn store(&self, session_id: &str, messages: &[Message]) -> Result<()> {
        let json = serde_json::to_string(messages)?;
        sqlx::query("INSERT INTO sessions (id, messages) VALUES ($1, $2) ON CONFLICT (id) DO UPDATE SET messages = $2")
            .bind(session_id)
            .bind(&json)
            .execute(&self.pool)
            .await?;
        Ok(())
    }

    async fn load(&self, session_id: &str) -> Result<Vec<Message>> {
        let row = sqlx::query_scalar::<_, String>("SELECT messages FROM sessions WHERE id = $1")
            .bind(session_id)
            .fetch_optional(&self.pool)
            .await?;
        match row {
            Some(json) => Ok(serde_json::from_str(&json)?),
            None => Ok(vec![]),
        }
    }

    // `search`, `sessions` and `delete` are required too; see the Memory trait
    // for their signatures and what they must return.
}
```

<Callout type="info">
This is a sketch: the `?` conversions from `sqlx` and `serde_json` errors into the crate's error type, and the three remaining methods, are yours to write. The trait is in `bricks-memory`.
</Callout>

## Extension points

| What | How |
|------|-----|
| Custom provider | `impl Provider` |
| Custom tool | `#[derive(Tool)]` or `impl Tool` |
| Custom permissions | `impl PermissionPolicy` |
| Custom memory | `impl Memory` (see above) |
| Custom hooks | `impl Hook` |
| Custom reporters | `impl Reporter` |
| MCP servers | `bricks::mcp::McpServerConfig`, in the agent's configuration |
| Skills | `SKILL.md` folders read by the skill loader, and `AgentBuilder::skills` |
| Graph memory | the `graph` feature of `bricks-memory` (not forwarded by the `bricks` facade) |
