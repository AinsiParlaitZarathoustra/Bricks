# bricks-types

Provider-agnostic types shared across all Bricks crates.

## Message

```rust
pub struct Message {
    pub role: Role,
    pub content: MessageContent,
    pub id: Option<String>,
    pub metadata: Option<MessageMetadata>,
}

pub enum Role {
    User,
    Assistant,
    System,
}

pub enum MessageContent {
    Text(String),
    Blocks(Vec<ContentBlock>),
}
```

Construct messages with helpers:

```rust
Message::user("Hello");
Message::assistant("Hi there!");
Message::system("You are helpful.");
message.get_text();  // -> Option<&str>

// Multimodal: text + files (images, video, audio, PDFs) in one call.
Message::user_with_files("Describe these", &["diagram.png", "clip.mp4"])?;
Message::user_with_media("Caption", vec![ContentBlock::from_path("a.png")?]);
```

See [Multimodal Input](/docs/multimodal) for the full file-passing API.

## ContentBlock

```rust
use bricks::types::{CitationsConfig, MediaSource, ToolResultContent};
pub enum ContentBlock {
    Text { text: String },
    Image { source: ImageSource },
    ToolUse { id: String, name: String, input: Value },
    ToolResult { tool_use_id: String, content: ToolResultContent, is_error: Option<bool> },
    Thinking { thinking: String, signature: String },
    RedactedThinking { data: String },
    Document { source: DocumentSource, title: Option<String>, context: Option<String>, citations: Option<CitationsConfig> },
    Audio { source: MediaSource },
    Video { source: MediaSource },
    ProtocolItem { protocol: String, item: Value },  // an opaque item a protocol needs echoed back verbatim
    Opaque,
}

// Image, document, audio and video payloads carry inline base64, a URL, or a
// file id from the provider's file store.
pub struct ImageSource {
    pub source_type: String,        // "base64" | "url" | "file"
    pub media_type: Option<String>, // e.g. "image/png"
    pub data: Option<String>,       // base64 (when source_type = "base64")
    pub url: Option<String>,        // remote URL (when source_type = "url")
    pub file_id: Option<String>,    // provider file id
}
// DocumentSource and MediaSource have the same shape.
```

Build them with the high-level constructors instead of by hand:

```rust
ContentBlock::from_path("photo.jpg")?;           // read file, sniff MIME, base64; audio and video get their own blocks
ContentBlock::image_bytes("image/png", &bytes);  // from raw bytes you hold
ContentBlock::image_url("https://x/y.png");      // remote image
ContentBlock::document_bytes("application/pdf", &pdf);
```

A block a provider cannot carry is refused before the request is sent, with `CerseiError::Unsupported`; it is never dropped silently.

## Usage

```rust
use bricks::types::CostEstimate;
pub struct Usage {
    pub input_tokens: u64,                      // uncached prompt tokens
    pub output_tokens: u64,                     // includes reasoning tokens
    pub total_tokens: u64,
    pub cache_creation_input_tokens: u64,
    pub cache_read_input_tokens: u64,
    pub reasoning_tokens: u64,                  // informational subset of output_tokens
    pub cost_usd: Option<f64>,                  // None when no price is known: unknown, never free
    pub cost_estimate: Option<CostEstimate>,    // how the estimate was made (tariff, partial)
    pub provider_usage: Value,                  // the provider's own usage object, as received
}
```

Supports merging:

```rust
usage.merge(&other_usage);
```

## StopReason

The provider's reason for its last response:

```rust
pub enum StopReason {
    EndTurn,
    MaxTokens,
    ToolUse,
    StopSequence,
    ContentFilter,
}
```

The result of a whole run is `Termination` in `bricks-agent` (`Completed`, `OutputTruncated`, `NoProgress`, `ContentFiltered`, `EmptyResponse`; `MaxTurns` exists only to read results stored before 0.4.8, `crates/bricks-agent/src/lib.rs:78-96`).

## StreamEvent

Events emitted during streaming completion:

```rust
pub enum StreamEvent {
    MessageStart { id: String, model: String, usage: Option<Usage> },
    ContentBlockStart { index: usize, block_type: String, id: Option<String>, name: Option<String> },
    TextDelta { index: usize, text: String },
    InputJsonDelta { index: usize, partial_json: String },
    ThinkingDelta { index: usize, thinking: String },
    SignatureDelta { index: usize, signature: String },  // must be echoed back verbatim
    ProtocolItem { index: usize, protocol: String, item: Value },
    ContentBlockStop { index: usize },
    MessageDelta { stop_reason: Option<StopReason>, usage: Option<Usage> },
    MessageStop,
    Ping,
    Error { message: String },
}
```

## CerseiError

```rust
pub enum CerseiError {
    Provider(String),
    ProviderStatus { status: u16, message: String, retry_after: Option<Duration> },
    Auth(String),
    Tool(String),
    Permission(String),
    RateLimit { message: String, retry_after: Option<Duration> },
    ContextOverflow { used: u64, limit: u64 },
    Cancelled,
    Config(String),
    Unsupported(String),     // a block or modality the model or its adapter cannot carry
    InvalidInput(String),    // e.g. a blank prompt with no attachment
    Mcp(String),
    Io(std::io::Error),
    Json(serde_json::Error),
    Http(reqwest::Error),
    Other(anyhow::Error),
}
```

`CerseiError::retry_after()` and `http_status()` expose the server's answer for a failed request. A `ProviderStatus` error keeps the `Retry-After` value; whether a request is retried is decided by the error's kind, not by the header.

All errors implement `std::error::Error`. Use `Result<T>` which is `std::result::Result<T, CerseiError>`.
